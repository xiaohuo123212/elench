# 接到智能体平台（初发 Trufar / Coze / Dify 这类）

> 一句话：**能接，而且不用改语言本体**。检查逻辑只有一份（`tools/elench_tool.py` 的
> `handle()`），外面套了四种壳：**MCP**、HTTP/OpenAPI、stdio、内嵌网页。
> 四种出来的结果逐字节相同——因为这四种都只是协议转换。

---

## 0. 先确认一件事：平台能不能访问到你的地址

这是唯一会让整件事卡住的地方，**先查这个再动手**：

| 平台的「工具」是怎么调的 | 你该怎么接 | 卡点 |
|---|---|---|
| **MCP 服务**（你说的这个） | 填 URL `http://<可达地址>:8080/mcp`；能跑本地进程就填命令 `--stdio` | 云平台只能 **HTTP**，`127.0.0.1` 它访问不到 |
| **HTTP / OpenAPI 插件** | `--http` 起服务，URL 填进平台 | 同上 |
| **代码沙箱 / 函数** | 把 `src/` + `tools/` 塞进沙箱，`--stdio` | 沙箱要有 Python ≥ 3.10；**我们零依赖，不用装包** |
| **HTML 内嵌代码** | 把 `tools/elench_playground.html` 整段贴进去 | 页面要能访问到我们的 HTTP 地址 |

> **零第三方依赖在这里是真优势**：整条工具链只用 Python 标准库，
> 所以「塞进别人家沙箱」这条路通常比「暴露公网服务」省事。

## 1. MCP 服务（推荐）

MCP 比 OpenAPI 插件省事的地方：**工具清单是运行时自描述的**——平台 `tools/list`
一次就知道有哪些工具、参数是什么，不用人对着表单手填 schema。

```bash
# ① stdio：平台能跑本地进程时用
python -B tools/elench_mcp.py --stdio

# ② streamable HTTP：云平台只能这样（POST /mcp）
python -B tools/elench_mcp.py --http --port 8080
#    → 平台里填 URL：http://<平台可达地址>:8080/mcp
```

| 方法 | 支持 |
|---|---|
| `initialize` | ✅ 回客户端要的协议版本（`2025-06-18` / `2025-03-26` / `2024-11-05`），带 `instructions` |
| `notifications/initialized` | ✅ 不响应（JSON-RPC 规定通知没有响应） |
| `tools/list` | ✅ 两个工具：`elench_check` / `elench_cost` |
| `tools/call` | ✅ 返回 `content[0].type="text"` + `structuredContent`（能直接读字段） |
| `ping` | ✅ |

**只实现这五个方法是故意的**：`resources` / `prompts` / `sampling` 对本工具没有意义，
声明了却不实现比不声明更坏（客户端会去调，然后失败）。

**不做 SSE 流式**：`GET /mcp` 会如实回一句"本服务不做 SSE，请 POST 一问一答"。
本工具没有长时间分块输出的场景，假装支持只会让客户端等不到东西。

### 两个工具

| 工具 | 作用 | 输入 |
|---|---|---|
| `elench_cost` | 算成本上界 κ，与 `.tu` 的 `target` 比，返回判决 | `tu`（可省）、`eln`、`compat`（可省） |
| `elench_check` | 静态检查：语法 / 类型 / 契约一致性 | `tu`（可省）、`eln`、`compat`（可省） |

**`compat: true`** 打开 C++ 兼容层（等价命令行 `--compat`）：`.cpp` 原样当 `.eln` 传进来就能查，
`using` / `typedef` / `auto` / `std::` / `void` / `+=` / 多声明符等写法都接受。
不传 `.tu` 时 κ 照样算得出来，判决是 `undeclared`（未声明契约——没有 target 可比）。

**故意不开放 `run` / `stats` / `measure`**：那三个会**真的执行**提交的代码。
在别人家的平台上开放它们等于免费送一个代码执行沙箱。

## 2. 内嵌网页（HTML 代码）

`tools/elench_playground.html` —— **单文件、零依赖、无任何外链**（CSS/JS 全内联，
不引 CDN），所以可以直接贴进平台的「HTML 内嵌代码」。

- 左边两个框填 `.tu` / `.eln`（自带一份能跑的示例）
- 右边出：判决徽章（`ok` / `debt` / `unknown`）、κ 表达式、解释、诊断列表（带改法）
- 顶部填我们的服务地址（会记在 `localStorage`；内嵌沙箱里存不了也不影响使用）
- 底下可展开**原始 JSON**，方便对照

页面调的就是第 3 节的 `POST /cost` 与 `POST /check`，所以**先把 HTTP 服务跑起来**：

```bash
python -B tools/elench_tool.py --http --port 8080
```

> 如果页面是被平台内嵌的，注意两点：① 平台要能访问到那个地址（`127.0.0.1` 只有你自己能访问）；
> ② 我们的服务已经带 `Access-Control-Allow-Origin: *`，跨域不用额外配。

## 2.5 平台「自定义代码」组件（HTML + JS）

平台的自定义代码组件只给三个钩子，而且**没有网络访问通道**：

```js
onMount(dom, value, onChange, props)
onUpdate(dom, data, prevData, props)
onUnmount(props)
```

所以正确的分工是 **工作流算、组件画**：

```
用户提交 .tu/.eln → 工作流调 MCP 工具 elench_cost → 结果写进变量
                  → 页面数据变化 → 组件 onUpdate(dom, data, prevData) 渲染
```

**HTML 里一行计算都不写**，因此不会出现"页面一套、命令行一套"的漂移。

四段代码在 `tools/trufar_component/`：

| 平台字段 | 文件 |
|---|---|
| 将显示的 HTML 内容 | `01-html.html` |
| 挂载事件响应（onMount） | `02-onMount.js` |
| 页面更新事件响应（onUpdate） | `03-onUpdate.js` |
| 取消挂载事件响应（onUnmount） | `04-onUnmount.js` |

数据契约（组件读 `data.elench`）就是 MCP `tools/call` 的 `structuredContent` 原样；
如果带上 `lines`（`[{n, hits}]`）会多画一条逐行热度条。详见
[`tools/trufar_component/README.md`](../tools/trufar_component/README.md)。

本地先看效果（不用等平台）：

```bash
python -B tools/trufar_component/preview.py     # 起服务器并开浏览器
node tools/trufar_component/selftest.js         # 18 条断言的功能验证（需要 node）
```

## 3. HTTP（OpenAPI 插件）

```bash
python -B tools/elench_tool.py --http --port 8080
python -B tools/elench_tool.py --openapi --server=http://<平台可达地址>:8080   # 生成 OpenAPI 3.0
```

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/health` | 活着没有、当前是否要求认证 |
| `POST` | `/cost` | 算 κ + 判决 |
| `POST` | `/check` | 静态检查 |

### stdio（沙箱 / 自定义进程）

```bash
echo '{"op":"cost","tu":"spec f(...) -> u64 { ... }","eln":"u64 f(...) { ... }"}' \
  | python -B tools/elench_tool.py --stdio
```

每行一个请求，每行一个响应。沙箱里只要 `src/` 与 `tools/` 的相对位置不变就能跑。

### 直接 `import`（平台是 Python 的）

```python
import sys; sys.path.insert(0, "tools")
from elench_tool import handle
handle({"op": "cost", "tu": "...", "eln": "..."})   # → dict
```

## 4. 请求与响应长什么样

请求（`tu` / `eln` 至少给一个）：

```json
{
  "op": "cost",
  "tu": "spec f(const vector<u64>& xs) -> u64 {\n  effects {};\n  target { time: { max: O(n) }, allocation: { max: 0 }, };\n}\n",
  "eln": "u64 f(const vector<u64>& xs) {\n  u64 s = 0;\n  for (auto x : xs) { s = s + x; }\n  return s;\n}\n"
}
```

响应：

```json
{
  "ok": true,
  "op": "cost",
  "module": "probe",
  "verdict": "ok",
  "functions": {
    "f": {
      "kappa": "2 + n(xs)×7 + 2",
      "verdict": "ok",
      "explanation": "达成：阶够，比值 ≈ 7.00",
      "allocation": "0",
      "allocation_verdict": "ok",
      "allocation_explanation": "达成：阶够"
    }
  },
  "exit_code": 0,
  "elapsed_ms": 111
}
```

### 两个字段别混（这条最容易用错）

| 字段 | 含义 | 什么时候会变 |
|---|---|---|
| `ok` | **工具跑完了没有** | 源码解析失败、参数不对、超时 ⇒ `false` |
| `verdict` | **代码合不合格** | `ok`（达成）/ `debt`（债务/超界）/ `unknown`（无法判定） |

违约的代码 `ok` **仍然是** `true`——因为工具正常工作了，是代码不达标。
把这两个混起来，平台会把"契约不达标"报成"工具坏了"，agent 就学不到东西。

多函数时 `verdict` 取**最差**的那个（`unknown` 比 `debt` 差，`debt` 比 `ok` 差），不粉饰。

## 5. 平台表单一般怎么填

| 表单项 | 填什么 |
|---|---|
| 名称 | `elench-cost-contract`（或「Elench 成本契约检查」） |
| 描述 | 给一段 Elench 源码，静态检查或算出成本上界 κ，并判定是否满足 `.tu` 里声明的 target。只读源码，不执行代码 |
| MCP / 地址 | `http://<平台可达地址>:8080/mcp`（stdio 那条路填命令 `--stdio`） |
| 鉴权 | 设了 `ELENCH_TOOL_TOKEN` 就选 **Bearer**，值填那个 token；没设就是无鉴权（只适合内网） |
| OpenAPI | `--openapi --server=…` 的输出，整段粘进去（走插件路线时才用） |
| HTML 内嵌 | `tools/elench_playground.html` 全文 |

**描述要写清楚"给源码文本，不是给文件路径"**——平台上的 agent 只会传字符串。

## 6. 限额与安全

```
单个字段 ≤ 256 KB · 整个请求 ≤ 512 KB
```

- **没有服务端硬超时**：处理是在本进程内同步调 `dsh.main`，只受**平台自己的**超时约束。
  `tools/elench_tool.py` 里的 `TIMEOUT_S = 30.0` **目前只是声明、没有接线**（2026-11-25 实测），
  需要硬超时的话得自己包一层子进程 + 计时。
- **没设 `ELENCH_TOOL_TOKEN` 时 `/health` 会明说 `auth: "none"`** —— 不假装有认证。
  对外网暴露前必须设 token。
- 本工具**不做**沙箱隔离：它只调 `check` / `cost`，这两个不执行用户代码。
  如果哪天要开 `run`，必须先自己加进程级资源限制。

## 6.5 想做成「网站」？先跑探针

「网站」和「平台组件」是两件事：组件受平台三个钩子约束，网站不受。三者的差别只在**谁来算 κ**：

| | 谁算 | 要不要服务器 | 首屏 | 能真算 |
|---|---|---|---|---|
| **A 后端站** | 我们的 Python 进程 | **要**（一个能被访问的地址） | 秒开 | ✅ |
| **B 纯静态 + Pyodide** | **浏览器里的 CPython** | **不要** | 首次 10–20 MB / 2–5 s | ✅ |
| **C 纯静态 + 预计算** | 构建时算好 | 不要 | 几十 KB | ❌ 只能看示例 |

**B 是根治"平台访问不到 `127.0.0.1`"的那条路**：页面里跑真的解释器，不需要地址、不需要穿透。

### 已经验证过了（2026-11-19，真浏览器）

运行时**就放在仓库里**（`tools/wasm/pyodide/`，13.2 MB，`fetch_runtime.py` 可重新取），
页面只从本地加载，**不联网**。用 Edge 无头模式真跑了一遍（`tests/cases/test_wasm_browser.py`）：

```
boot 完成：1039 ms · Pyodide 0.27.2 · 60 个模块
合规：κ = 2 + n(xs)×7 + 2            verdict = ok
违约：κ = 2 + n(xs)×(2 + n(xs)×7) + 2 verdict = debt
算一次耗时：511.8 ms（首次含预热）/ 4.5 ms（之后）
```

**与命令行逐字符相同。** 也就是说：网站可以做成**纯静态页**——不需要服务器、
不需要公网地址、不需要内网穿透，这正好根治"平台访问不到 `127.0.0.1`"。

#### 这一步挖出来的两个真问题

1. **`cost_domain/cost_interp.py` 在 Python ≤ 3.13 上根本 import 不了**：
   注解 `-> Dict[str, Any]` 里用了 `Any` 却没 import，而 ≤3.13 的注解是**eager 求值**的。
   本机是 3.14（PEP 649 惰性求值）所以一直看不见——**`requires-python >= 3.10` 这条声明
   在 3.10–3.13 上是假的**。已修（补 `Any`），并加了
   `tests/cases/test_annotations_resolve.py`：主动访问每个模块的注解，任何版本都能抓到。
2. **`ffi_c` 在模块级硬 import `ctypes`**，导致整个包在浏览器（WASM）里连 import 都过不去。
   已改成"可用就用、没有就退化"，真调 FFI 时给一条清楚的话。

### 怎么自己跑

```bash
python -B tools/wasm/fetch_runtime.py     # 一次性：取运行时（13.2 MB，已入库可跳过）
python -B tools/wasm/probe.py             # 起服务器 + 开浏览器，点按钮
node tools/wasm/headless_check.mjs <url>  # 或者无头跑（不需要人点）
```

### `src/core_api.py`：三个壳的唯一核心

```
tools/elench_tool.py  ─┐
tools/elench_mcp.py   ─┼─→ core_api.check() / core_api.cost()  ─→ dsh 的检查/成本函数
网页（Pyodide）        ─┘
```

它**不重写任何逻辑**，就是在本进程里调 `dsh.main([... "--json"])` 再把 stdout 的 JSON 解析出来，
所以与 CLI 逐字段相同（`tests/cases/test_core_api.py` 钉住了这条，含 WASM 模拟）。
顺带把每次调用的开销从 **116 ms 降到 8 ms（14×）**。
