## 三、数字都对得上哪儿

文档里的规模数字（样例数、测试文件数、子命令数、实现行数）**只有一处来源**：

```bash
python -B tools/audit_numbers.py --json     # 样例 17 / 测试 138 / 子命令 19 / 实现 59 文件 3.6 万行
```

**别手抄数字**：手抄的会过期，绑定的不会（`tools/doc_numbers.py` 会把文档里的数字绑到来源上）。

## 四、维护规则

| 规则 | 内容 |
|---|---|
| **代码先于文档** | 参考类文档与实现不一致时，**以 `src/` 为准**，改文档 |
| **文档里的代码必须能编译** | `tests/cases/test_doc_snippets.py` 会真的编译 ` ```elench ` 块；纯语法模板要写 `// doc-template: <原因>` |
| **示例不抄第二遍** | 用 `<!-- @include 样例/x.tu#region -->` 注入，`python src/sync_docs.py` 同步 |
| **改完跑门禁** | `python -B tools/gates.py`（10 道门） |
| **不要手改生成的表** | `内建函数.md` 由 `tools/gen_builtins_doc.py` 生成 |
| **不 push** | 提交与推送由维护者决定 |
