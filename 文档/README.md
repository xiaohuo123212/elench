## 一、目录结构

```
文档/
├── 设计/
│   ├── 目前设计/      ← 现在成立的设计（唯一要读的部分）
│   ├── 未来计划/      ← 还没做、准备做的事
│   └── 归档/          ← 已实现完的、明确不做的、过期的
├── 实验/              ← 测量与对照实验
└── 其他/              ← 与写这个语言不直接相关（大创、入门、笔记）
```

**判据**：

| 目录 | 什么进去 |
|---|---|
| **目前设计** | 现在读它就能照着写代码 |
| **未来计划** | 现在还没实现，但已经想清楚要做 |
| **归档** | 已经做完的、决定不做的、被取代的 |
| **实验** | 设计好要跑、或已经跑过的测量 |
| **其他** | 换个语境才用得上（申报、教学、笔记） |

| 文件 | 内容 | 稳定性 |

| `AI语言设计规格.md` | 条款正文（**v0.53**）：C/N/D/M/G/T/H/K/LIE 全家族 | 每版 +0.01 |
| `语法设计.md` | 说明文档（例子、C++ 对照、意图），**非规范** | |
| `决定清单.md` | 已拍板的 36 条决定，按 ✅/⚠️/🔴 分级 | |
| `设计缺口.md` | **唯一的未解决缺口清单**（按 P0 / P1 / P2 / 挂起 分组）+ 已解决条目的索引表 | |
| `归档/缺口-已解决.md` | 已解决缺口的全文（保留「为什么这样解决」） | |
| `归档/规格历史/` | v0.62–v0.67 规格全文快照 | |
| `待定与存疑.md` | 存疑、未定结构问题、推迟项重开条件；含规格 §20 迁入的 **O-1…O-9** | |
| `规格审计报告-v0.15.md` | **进行中的工单**（不是历史）：71 条问题的修复状态。编号与缺口不同源 | |
| `待办（v0收缩清单）.md` | **C1–C11 唯一编号表**，后续路线 §4 按它引用 | |
| `_internal/` | **内部材料**：对齐计划、归类审计、竞争力评估。**不对外** |
| `样例/calculator.tu` | **声明**：常量、枚举、10 个 `spec` | |
| `样例/calculator.eln` | **实现**：10 个 `fn`，零声明 | |

> **规格与语法设计的关系**：规格说「必须怎样」（**含文法**），语法设计说「长什么样、为什么」。
> 冲突时：**条款与文法都以《AI语言设计规格》为准**。
> `语法设计.md` 是**说明文档**，**不是规范**。
> `目标.md` 是**愿景文档**，**不参与冲突裁决**——它的示例是示意，以规格为准。

## 九、维护规则

| 规则 | 内容 |
|---|---|
| **改条款** | 规格 + 语法设计**同时**改 |
| **拍板** | 进 `决定清单.md`；理由不牢的进 `待定与存疑.md` |

| **过期文档** | 移进 `设计/归档/`，不删 |
| **版本号** | 规格每次实质修改 +0.01，变更记录写在文件头 |
| **批量改文档** | **只用行号定位 + 单引号字符串**——带反引号的 PowerShell 替换已伤过两次 |
