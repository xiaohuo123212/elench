> 面向**第一次接触**的人。不需要读规格，跟着敲就能看到"成本声明被违反"的完整过程。
> 想要细节：语法看 [语法清单](设计/目前设计/语法清单.md)、内建看 [内建函数](设计/目前设计/评估/对外文档副本/内建函数.md)、规格看 [AI语言设计规格](设计/目前设计/AI语言设计规格.md)。

---

## 0. 它是什么（一句话）

> **Elench 不证明你的程序快；它证明你写下的"快"的声明是不是真的。**

你写下 `target`（"这个函数不超过 n log n"），编译器从实现推出 κ（真实上界），**两者一比**：
**达成** 或 **债务**。债务在 CI 里可以变成**拒绝构建**。

## 2. 第一个程序（5 分钟）

新建两个文件，**放在同一目录**：

**`hello.tu`** —— 声明（人写，几十行，这是别人要签的部分）

```elench
spec hello() -> u64 {
    effects {};
    target { time: { max: 3 }, allocation: { max: 0 } };
}
```

**`hello.eln`** —— 实现（可以是模型写的，可以整份重写，**不含任何声明**）

```elench
func hello() -> u64 {
    return 42;
}
```

跑：

```bash
python src/elench.py check hello.tu      # 语法/类型/契约：通过
python src/elench.py cost  hello.tu      # 推 κ 并和 target 比
python src/elench.py run   hello.tu      # 真的执行 → 42
```

`cost` 会打印类似：

```
hello  κ ≤ 3    target 3    达成
```

## 3. 第一个"被抓到"的违反（10 分钟）

把实现换成一个**看起来对、其实阶错了**的版本：

```elench
func sum_all(Vec<u64>& xs) -> u64 {
    u64 s = 0;
    u64 i = 0;
    while (i < xs.length()) { s = s + xs[i]; i = i + 1; }
    return s;
}
```

声明：

```elench
spec sum_all(Vec<u64>& xs) -> u64 {
    effects {};
    target { time: { max: O(xs.length()) }, allocation: { max: 0 } };
}
```

```bash
python src/elench.py cost  sum_all.tu     # 达成（线性对线性）
python src/elench.py build sum_all.tu     # 通过
```

现在把声明改成**更紧**的 `O(log n)`：

```bash
python src/elench.py cost  sum_all.tu     # 债务：κ 是 n，target 是 log n
python src/elench.py build sum_all.tu     # 默认：报告债务，仍然通过
python src/elench.py build sum_all.tu --deny-debt   # 拒绝构建，exit=1
```

> **这就是全部的核心**：**声明可以收紧，门禁会告诉你收得对不对**。

## 4. 三个动词（5 分钟）

| 动词 | 命令 | 你得到什么 |
|---|---|---|
| **query** | `cost` | κ 的表达式（如 `1 + n(xs)×17 + 17`）与达成/债务 |
| **violate** | `build --deny-debt` | **exit 1**：声明被打破，构建被拒 |
| **repair** | 改 `.eln`（换实现/换算法）→ 再 `cost` | 比值回到 1.00 |

**注意**：**全程没有运行被检查的程序**。κ 来自源码结构，不来自测量。

## 6. 五个最常见的错误（与修法）

| 现象 | 原因 | 修法 |
|---|---|---|
| `E-Fn-NoSpec` | `.eln` 里有函数但 `.tu` 里没声明 | 先写 `spec`，再写实现 |
| `E-Spec-SigMismatch` | 参数个数/类型/返回与声明不一致 | 对齐签名；**声明是唯一真源** |
| `E-Effect-Missing` | 实现里调用了副作用函数，但 `effects {}` 里没写 | 在 `.tu` 里补 `effects { fs };` |
| `E-Dispatch-NoTable` | 用了 `?!` 却没有分档表 | 先 `measure` 生成表，或去掉 `?!` |
| 债务（build 通过但 cost 报红） | κ 超过 `target` | 换实现，或**经评审后**放宽 target |
