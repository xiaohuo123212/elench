# Elench 工作台（纯静态网页）

> 左边贴你的 `.cpp`（**不用改**），右边看 `κ` 与判决。**全部在浏览器里算**——
> 没有服务端计算，所以它是个可以丢到任何静态托管上的网页。
>
> **打开就是 C++ 模式**：兼容层默认开，默认示例是「一份没改过的 C++ + 一份契约」→ `达成`。

```bash
python -B tools/site/serve.py          # 起服务器并打开 http://127.0.0.1:<端口>/
```

---

## 0. 它能做什么

| 做 | 不做（还没有） |
|---|---|
| **贴 `.cpp` 原样**（C++ 模式默认开） | 执行代码、看运行时输出（那要 trace，见 §5） |
| 写 `.tu`（契约）与 `.eln`（实现） | 逐行热度、CFG 覆盖图（计划中） |
| 算 κ，与 target 比，出**达成 / 债务 / 无法判定** | 逐行热度、CFG 覆盖图（计划中） |
| 静态检查，出**诊断码 + 行列 + 改法** | 多文件模块（一次一个模块） |
| 四个一键示例：**C++ + 契约** / C++ 原样 / 违约 / 语法错 | 保存历史（刷新就没了） |

**为什么值得这么干**：κ 现在能在一个**不需要安装、不需要服务器、不需要联网**的页面里算出来，
而算它的仍然是 `src/` 里那份**唯一的**实现（`core_api` → `dsh` 的检查/成本函数）。
不存在"网页版和命令行版算出来不一样"的可能。

## 0.5 C++ 模式：`.cpp` **原样丢进来**就能算 κ

右上角有个 **「C++ 模式」** 开关，等价于命令行加 `--compat`。打开之后**不用改代码**：

```cpp
#include <vector>
#include <cstdint>
using namespace std;

uint64_t sum_all(const vector<uint64_t>& xs) {
    uint64_t s = 0;
    for (size_t i = 0; i < xs.size(); i++) {
        s += xs[i];
    }
    return s;
}
```

点 **「C++ 原样」** 示例按钮就是这一份，页面实测结果：

```
κ ≤ 2 + 2 + n(xs)×16 + 16 + 2        判决：未声明契约
```

**为什么是「未声明契约」而不是「达成」**：没有 `.tu` 就没有 target 可比。κ 照样算得出来，
只是"合不合格"这件事没有承诺可判。想要判决，就把 `.tu` 补上（只写 `spec` + `target`，
实现仍然用你原来的 `.cpp`）。

**兼容层接受哪些 C++ 写法**（§5.5 列了十种**特殊改写**；完整能力见 [命令一览 §0](入门/命令一览.md)，还有强转 / 迭代器 / `class` / 运算符重载 / 模板 / 宏）：
`struct` 在 `.eln` 里、`using` / `typedef`、`auto x = e`、`T{a,b}`、`f(xs.begin(), xs.end())`、
`std::` 白名单、返回类型 `void`、函数前的 `static`、多声明符 `u64 a = 1, b = 2;`、直接构造。

**它不做的**（别指望）：
- **不读**找不到的头：标准头静默忽略；引号/尖括号头**能找到就内联**（按包含者所在目录与 `ELENCH_INCLUDE_DIRS` 搜），**找不到**才报 `E-Lex-IncludeUnresolved`。库符号仍建议在 `.tu` 声明，或写 `extern … from "lib"`。
- **原生语法没有**这些：`class` / 成员函数 / 运算符重载 / 类模板 / 宏系统。但 **C++ 模式下会降级**：`class`→`struct`、成员函数→`P_get`、`operator<`→`P__op_lt`、类模板→单态化（`Box__u64`）、宏→预处理展开。真正的硬缺口是**语义层**（数据/行为分离、值语义），见 [能力边界](能力边界.md) §2.1。

**实测口径**（`demo/corpus/01_sorting.cpp`，41 行，一个字没改）：

| 命令 | 结果 |
|---|---|
| `check x.eln`（不开 compat） | ✗ `E-Keyword-Unsupported`（`using`）+ `E-Parse-SkippedBody` 跳了 42 行 |
| `check x.eln --compat` | ✓ 通过（4 个函数） |
| `cost x.eln --compat` | κ 算出来了：`insertion_sort` / `merge_halves` / `merge_sort` |

## 1. 它是怎么跑起来的

```
浏览器
 ├─ /pyodide/…            13.2 MB 运行时（CPython 编成 WASM，仓库里就有一份）
 ├─ /modules.json         61 个 .py 的清单
 ├─ /src/**/*.py          源码，逐个读进来写进 Pyodide 的文件系统
 └─ import core_api       →  check() / cost()      ← 与命令行同一份逻辑
```

页面加载时做的事：读运行时 → 灌 61 个 `.py` → `import core_api` → 自动算一次示例。
**首次约 1–2 秒**（本地磁盘，不联网）；之后每次计算 **3–7 ms**。

## 2. 部署：导出成静态目录

```bash
python -B tools/site/serve.py --export dist
```

产出（**16.4 MB / 74 个文件**；数字随 `src/` 变化，以 `--export` 自己的输出为准）：

```
dist/
  index.html        ← 页面（样式与脚本全内联，零外链）
  modules.json
  src/              ← 工具链源码（页面会把它们灌进 Pyodide）
  pyodide/          ← 运行时
```

把这个目录丢到 GitHub Pages / 学校服务器 / nginx 就能用，**目标机器不需要 Python**。
本地验一下：

```bash
cd dist && python -m http.server 8000 --bind 127.0.0.1     # 打开 http://127.0.0.1:8000/
```

> 为什么本地也要起服务器：浏览器禁止 `file://` 下 `fetch` 读 `.wasm` 与 `.py`。
> 双击打开会看到页面明确报"运行时加载失败"，并说清原因。

## 3. 它凭什么是可信的

**每一层都有测试钉住，而且都跑在门禁里**：

| 层 | 测试 | 钉住什么 |
|---|---|---|
| 进程内核心 == CLI | `test_core_api.py` | 4 个用例逐字段相同 |
| 没有宿主能力也能算 | `test_core_api.py` | 禁掉 `subprocess`/`ctypes`/`socket` 后仍算出同样的 κ |
| **真浏览器里也算得对** | `test_wasm_browser.py` | 无头 Edge + Pyodide，断言 κ 字符串与判决 |
| 注解在运行期可求值 | `test_annotations_resolve.py` | 防住"3.14 看不见、3.12 直接炸"那类问题 |

`test_wasm_browser.py` 在没装 node / 没浏览器 / 运行时不在时**明确说跳过**，不假装通过。

## 4. 已知边界（写在页面上，也写在这里）

| 现象 | 原因 |
|---|---|
| 首屏要 1–2 秒 | 13.2 MB 运行时；只在第一次加载，之后同页面内复用 |
| 打印不了运行结果 | 页面**不执行**代码——只做静态检查与成本推导。要跑请用 `elench run` |
| 大输入会慢 | 解释器本身是树遍历的（约 0.55 M ops/s）；这是语言的定位（小输入算法原型） |
| 诊断只有英文码 + 中文消息 | 诊断码是稳定的，消息是给人看的 |

## 5. 下一步（按价值排序）

1. **逐行热度**：要在 `interp._stmt()` 加一个 trace 钩子（那里已经有 `if _COUNT: _bump()`，
   同形状），然后页面把行命中次数画成热条。**做一次，③ 白捡**——CFG 覆盖要的也是"行→次数"。
2. **CFG 覆盖图**：`src/cfg.py` 已经有 CFG（节点=语句、`succ` 边、`uses/defs/muts`、liveness），
   只缺"导出成 JSON"和"画出来"。布局用确定性的分层布局，**别上力导向**。
3. **单步 / 变量时间线**：依赖同一个 trace，另外要变量快照策略（增量记录，否则数据量爆炸）。

## 6. 与平台组件的关系

| | 工作台（本页） | 平台组件（`tools/trufar_component/`） |
|---|---|---|
谁算 | **页面自己算**（Pyodide） | **工作流算**（调 MCP 工具），组件只渲染 |
要不要服务器 | 静态托管即可 | 不需要（但工作流要能调到 MCP） |
能做什么 | 完整交互、能改代码、能算 | 平台里的一个卡片，显示工作流给的结果 |

两边都用 `core_api` 当唯一核心，所以数字一定一致。
