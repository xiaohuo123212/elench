# 入门：把你手上的 C++ 变成可核对的成本契约

> 你已经会写 C++。这份文档**不教你一门新语言**——它只做两件事：
> ① 让你现有的 `.cpp` **一个字不改**就被检查、被算出成本上界 `κ`；
> ② 教你怎么用**三行** `.tu` 给某个函数加一条"承诺"，让工具替你核对它到底做没做到。

---

## 0. 三十秒版

```bash
pip install -e .                                  # 一次：提供 elench 命令，零依赖

elench cost 我的文件.cpp --compat                 # ← 就这么用：实现在 .cpp 里，不用改
```

它不运行你的程序，而是**读源码**给出一串式子：

```text
  · count_above  κ ≤ 2 + 2 + n(xs)×20 + 20 + 2
```

`κ` 是**操作数上界**（不是时间）：编译器从语句结构推出来的"最多花多少步"。
它比 `O(n)` 更强——连常数都写出来了。

## 1. 装

需要 **Python ≥ 3.10**，**零第三方依赖**。

```bash
git clone https://github.com/xiaohuo123212/elench.git
cd elench
pip install -e .
```

> 只 clone 不装也能用：把下面所有 `elench` 换成 `python src/elench.py`。

**如果你打算主要用它检查 C++ 代码**，把兼容层一次设开，之后不用每条命令都加 `--compat`：

```bash
export ELENCH_COMPAT=1        # Linux / macOS
set ELENCH_COMPAT=1           # Windows cmd
$env:ELENCH_COMPAT = "1"      # Windows PowerShell
```

下面每条命令我都显式写 `--compat`，方便你复制；设了环境变量就可以省掉它。

## 2. 第一步：把你的 `.cpp` 丢进去，一个字不改

随便抓一个你写的函数。比如这个（**41 个字符的改动都不需要**）：

```elench
#include <vector>
using namespace std;

// 数一数有多少个元素比阈值大
int count_above(const vector<int>& xs, int threshold) {
    int n = 0;
    for (int i = 0; i < xs.size(); i++) {
        if (xs[i] > threshold) {
            n += 1;
        }
    }
    return n;
}
```

存成 `count_above.eln`（后缀改成 `.eln` 就行，内容不动），然后：

```bash
elench check count_above.eln --compat
```

```text
⚠ 1 条警告（不阻断构建）
  ⚠ I-Fn-NoSpec-Module @1:1  本模块没有 .tu，成本契约不参与判定（1 个函数未声明契约；要契约就补 <模块>.tu，仓库自检用 --strict）

module count_above

  !     count_above  有体  —       state=unchecked 未声明契约（没有 .tu）

✓ 通过（1 个函数，其中 0 个无体）
```

**"未声明契约"不是错误**：语法和类型都过了，只是**还没有承诺**，所以没有"合不合格"可判。补 `.tu` 是下一步。

```bash
elench cost count_above.eln --compat
```

```text
  · count_above  κ ≤ 2 + 2 + n(xs)×20 + 20 + 2
                 未声明契约（没有 spec）：不参与判定、不算债务、不算错误
```

**`κ` 已经出来了**：`n(xs)` 是 `xs` 的长度，系数 `20` 是"每轮循环约 20 个操作"，
首尾两个 `2 + 2` 和 `+ 20 + 2` 是循环外的固定开销。**它比 `O(n)` 强——连常数都写了。**

想真跑一下（不需要编译，解释器直接执行）：

```bash
elench run count_above.eln --fn=count_above --vec=1,2,3 --u64=2 --compat
```

```text
1
```

（`1,2,3` 里只有 `3 > 2`，所以是 `1`。stderr 上还会多一行「本模块没有 `.tu`…」——
那是提醒，不是错误。）

## 3. 第二步：加三行 `.tu`，`κ` 就有判决了

`κ` 是事实，但"合不合格"要看你**承诺了什么**。承诺写在同名 `.tu` 里（实现仍然一个字不改）：

**`count_above.tu`**

```elench
spec count_above(const vector<int>& xs, int threshold) -> int {
    effects {};
    target { time: { max: O(xs.size()) }, allocation: { max: 0 }, };
}
```

```bash
elench cost count_above --compat
```

```text
module count_above

  ✓ count_above  κ ≤ 2 + 2 + n(xs)×20 + 20 + 2
                 分配 ✓ alloc ≤ 0   (target 0)
                 达成：阶够，比值 ≈ 20.00

✓ 所有函数都在 target 之内
```

**`达成`**：`κ` 是 `O(n)`，承诺也是 `O(n)`，**比值 20.00** 就是"常数差多少倍"。

注意这一步发生了什么：**你没有改实现，只加了一份承诺**。这就是整套东西的用法——
实现是一次性的、随便重写；承诺是持久的、要人签。

有了 `.tu` 之后，`stats` 才能按 `--vec` / `--u64` 装配实参（**没有 `.tu` 时它会拒绝**，
因为它不知道形参该给什么类型）：

```bash
elench stats count_above count_above --ops --vec=1,2,3 --u64=2 --compat
```

```text
{"function": "count_above", "args": [3, 2], "iterations": 3, "ops": 61, "value": "1", ...}
```

`ops` 与 `κ` **同一个单位**（操作数），所以"`κ` ≥ 实测 `ops`"是一条能判真假的命题。

## 4. 第三步：让它红（承诺被打破）

把 `target` 收紧一格（`O(n)` → `O(log n)`），**实现一个字不动**：

```elench
spec count_above(const vector<int>& xs, int threshold) -> int {
    effects {};
    target { time: { max: O(log(xs.size())) }, allocation: { max: 0 }, };
}
```

```bash
elench cost count_above --compat
```

```text
  ▲ count_above  κ ≤ 2 + 2 + n(xs)×20 + 20 + 2
                 **超标**：阶不够，比值 ≈ 549755813888.65
```

**`▲` 是债务，不是错误。** 默认口径下 `build` **只记账、不拦截**：

```bash
elench build count_above --compat              # ✓ 通过：记债务，退出码 0
elench build count_above --compat --deny-debt   # ✗ 拒绝构建，退出码 1
```

```text
✗ 拒绝构建：1 处超出 target（--deny-debt）：count_above[time]
```

**为什么默认宽松**：新项目一上来全是债，直接拦会逼所有人去改 `target`——
而"谁写实现谁改目标"正是最该防的作弊。**要门禁就显式加 `--deny-debt`。**

### 三个动词

| 动词 | 命令 | 你得到什么 |
|---|---|---|
| **查** | `elench cost` | `κ` 的表达式 + 达成 / 债务 / 无法判定 |
| **拒** | `elench build --deny-debt` | 退出码 1：承诺被打破，构建被拒 |
| **修** | 改 `.eln`（换写法 / 换算法）→ 再 `cost` | 比值回到 1.00 左右 |

**全程没有运行被检查的程序**：`κ` 来自源码结构，不来自测量。

## 5. C++ 写法支持到哪（实测矩阵）

大多数 C++ 写法**本来就认**，不用加 `--compat`。下面这张表是逐条实测的
（✓ = 通过，✗ 后面是它报的诊断码）：

| 你写的 | 不加 `--compat` | 加 `--compat` |
|---|---|---|
`int` / `const int` / `for (int i…)` / `vector<int>` | ✓ | ✓ |
`elem += 1`、`xs[i]`、`max(a,b)`、`if/while/for` | ✓ | ✓ |
`#include <vector>`（**标准头静默忽略**） | ✓ | ✓ |
`std::vector` 前缀 | ✓ | ✓ |
返回类型写 `void` | ✓ | ✓ |
`struct P { u64 a; };` **写在 `.eln` 里** | ✗ `E-Ai-HasDecl` | ✓（用它就行；`.eln` 只放函数体是设计边界）
`using X = Y;` / `typedef X Y;` | ✗ `E-Keyword-Unsupported` | ✓ |
`auto x = expr;` | ✗ `E-Keyword-Unsupported` | ✓ |
`T x{1, 2}` / `vector<u64> v{1,2,3}` | ✗ `E-Parse-Expected` | ✓ |
`f(xs.begin(), xs.end())` | ✗ `E-Call-UnknownMethod` | ✓ |
`static` 开头的函数 | ✗ `E-Keyword-Unsupported` | ✓ |
`u64 a = 1, b = 2;`（多声明符） | ✗ `E-Parse-Expected` | ✓ |
`vector<u64> v(n, 0)`（直接构造） | ✗ `E-Call-Undeclared` | ✓ |
`static_cast<u64>(x)` | ✗ `E-Cast-Unsupported` | ✓ |
`for (auto it = xs.begin(); it != xs.end(); ++it)` | ✗ `E-For-NoIterator` | ✓ |
`class P { … };` 当 `struct` 用 | ✗ `E-Keyword-Unsupported` | ✓ |
**C 强转** `(int)x` / `(u64)xs.size()` | ✗ `E-Cast-CStyle` | ✓（等价于 `x as T`） |
**`#include "x.h"`**（自己的头） | ✗ `E-Lex-IncludeUnresolved` | ✓（内联 + 原型翻 `extern`） |
| **`#include <lib/x.h>`**（尖括号 + 搜索路径） | ✗ `E-Lex-IncludeUnresolved` | ✓（按 `ELENCH_INCLUDE_DIRS` 找，找到就内联；标准头仍静默忽略） |
| **成员上的 `mutable` / `inline` / `volatile` / `constexpr`** | ✗ `E-Keyword-LongForm` | ✓（纯拼写，跳过） |

### 已知缺口（明确不做 / 做不了，写在这里免得再问）

| 缺口 | 为什么 | 你现在能怎么办 |
|---|---|---|
**宏机制**：`##` 拼接、函数宏的边界、条件宏里的 `#error` | 本语言的 `#define` 是**文本替换**级别，不做 token 拼接，也不求值 `#if` 的复杂表达式 | 手写展开后的代码；或把那段挪到 C 侧（`extern … from "lib"`） |
**`.eln` 里不许有声明**（`E-Ai-HasDecl`） | **设计如此**：类型、`const` 常量属于 `.tu`，实现文件只放函数体 | 把声明挪到 `.tu`——**但那就不是 0 改动了**，这一点要认 |
**`static` 局部变量** | 本语言没有函数级静态存储 | 提到模块级，或改成显式传入的累加器 |
**模板只做单态化** | 偏特化 / SFINAE / 可变参数 / 非类型参数 / 模板元编程都没做 | 改用具体类型写重载（本语言本来就能重载） |

实测数据见 [真库探针](真库探针.md)：47 个真库探针里，移植口径过 9 个、FFI 口径过 20 个；
`demo/probe-libs/` 的 9 个手写探针过 1 个，其中 5 个卡在上面第二条（设计边界）。

### 已经能用的（别被旧文档劝退）

| 写法 | 状态 | 说明 |
|---|---|---|
**C 风格强转 `(int)x` / `(u64)xs.size()`** | ✓ 开 `--compat` 可用 | 只认**内建标量**拼写（`int` / `u64` / `unsigned long` / `double`…），因为它们不可能是变量名；语义**就是** `x as T`，所以 κ 与 `as` 逐字符相同。别名 / struct 名仍拒绝 |
**`#include "你自己的头"`** | ✓ 开 `--compat` 可用 | 真的读进来：递归内联，并把头里的**函数原型**翻成 `extern name(…) -> T from "<头>";`，于是调用能过、κ 里显示 `ext(名字)`。解析不到的头仍报 `E-Lex-IncludeUnresolved`（不假装读过） |
**类成员函数**（读/写字段、带参、互调） | ✓ 开 `--compat` 可用 | 降级成自由函数（第 13 条） |
**`#include <真库的头>`** | ✓ 开 `--compat` 可用（要设 `ELENCH_INCLUDE_DIRS`） | 与引号形式同一套：找到就内联。**找不到仍然报错**，不假装读过 |
**`#warning "…"`** | ✓ 开 `--compat` 可用 | 只打印提醒、不改变语义；严格模式仍报不支持 |
**宏**：`#define` 对象宏 / 带参宏 / 嵌套 / `#ifdef` 条件编译 | ✓ 本来就能用 | 不需要 `--compat` |
**函数模板** `template <typename T> u64 len(const vector<T>& xs)` | ✓ 开 `--compat` 可用 | 在**调用点单态化**：`len(xs)`（`xs` 是 `vector<u64>`）实例化成 `len__u64(const vector<u64>&)`，调用点改成它——C++ 编译器做的也是这件事。**实测 κ 与手写具体函数逐字符相同**。推断不出类型时报 `E-Type-InferFailed` 并说明怎么改 |
**运算符重载** `operator<` / `==` / `[]` / `+` …（自由与成员两种写法） | ✓ 开 `--compat` 可用 | 把 `a < b` **改写成** `P__op_lt(a, b)`——不是"允许通过"：κ 必须把被调函数的成本算进去，否则它就不是上界了。**实测 `a < b` 的 κ 与 `less(a, b)` 逐字符相同** |
**类模板** `template <typename T> struct Box { T v; };` | ✓ 开 `--compat` 可用 | 按使用点实例化成具体 struct（`Box<u64>` → `Box__u64`），**成员函数也跟着实例化**（`P__u64_sum`）。实参按位置对应，不需要推断。**κ 与手写具体 struct 逐字符相同** |

### 还不支持的（**会真挡住**，别指望）

| 写法 | 报什么 | 现状 |
|---|---|---|
**成员默认值** `u64 a = 5;` | `E-Compat-AggregateArity` | 写 `P p{5};` 显式给值 |
**`P p = P(3)`（构造函数调用）** | `E-Call-Undeclared` | 构造函数的**声明**能解析，`P(3)` 这种**函数式**构造调用不行；写 `P p{3};`

**顺手记一条**：`int` 在这里是 **64 位**（不是 C++ 的 32 位），而且**不做范围检查**——
`int x = 2^63` 原样存得下。要 32 位就写 `i32` / `int32_t`。
完整对照见 [C++ 程序员上手清单](C++惯用法对照.md)。

## 6. 契约的子句：`.tu` 里能写什么

```elench
// doc-template: 语法模板（name / params 是占位符），不参与编译检查
spec name(params) -> RetType {
    effects { fs, io };                 // 副作用集合；纯函数写 {}
    sizes n = xs.size();                // 给形状量起名（缩写，不是局部变量）
    target {
        time:       { max: O(n) };      // 时间上界（阶）
        allocation: { max: 0 };         // 分配上界：**按字节精确判**
    };
    requires xs.size() > 0;             // 前提：运行期会被检查
    guarantees sorted(ret);             // 语义承诺：可检查的进运行期
    repeats log(n) + 1;                 // 循环圈数上界：运行期会被检查
    recursion depth <= 8;               // 递归深度：**有递归就必须写**
    external { read_file: O(n) };       // 外部调用登记：不登记就按 ⊤
    benchmodel {                        // 测量用的输入规模模型
        data { xs = random_u64s(); }
        scale { xs in range(1, 4096, *2); }
    };
}
```

| 子句 | 一句话 | 违反时 |
|---|---|---|
| `target` | 我承诺的成本上界 | `cost` 判债务 / `build --deny-debt` 拒绝 |
| `effects` | 会不会 IO / 分配 / 改文件 | `E-Effect-Missing` |
| `requires` | 调我的人必须保证的事 | 运行期 `InterpRequiresViolated`（**不是** `E-` 码），消息里有函数名 |
| `guarantees` | 我保证的事 | 可检查的进运行期并报 `E-Guarantee-Violated`；不可检查的给警告 |
| `repeats` | **以它为条件的那个 `while`** 最多转几圈 | 跑超了 → `E-Repeats-Exceeded`；**写在别的函数上不生效**，只给警告 `W-Repeats-Unused` |
| `recursion depth` | 递归最多几层 | `E-Recursion-Depth-Exceeded`；**不写就报 `E-Recursion-Unbounded`** |
| `sizes` | 给形状量起名 | 右侧不是形状量 → `E-Sizes-NotShape` |
| `external` | 外部函数登记成本 | 不登记 → `E-Call-Undeclared` |
| `benchmodel` | 测量时怎么造输入 | 缺了 `measure` 直接拒绝："没有 benchmodel.scale，无法确定测量点"，退出码 2 |

> **这张表是逐条造反例实测过的**（2026-11-25）：每一条都写了故意违反它的样例，
> 跑出来的码与右列一致。有两处比"想当然"更严格，读的时候注意：
> `repeats` **只约束「以它为条件的 `while`」**（写在自己的函数上不会生效，只给
> `W-Repeats-Unused`）；`requires` 违反时抛的是 `InterpRequiresViolated`，**没有**
> `E-` 前缀的码。

**这些都不是注释**：写了就被核对，而且**总是开**（没有开关）。
理由一句话：**可关掉的断言等于默认关掉的断言。**

### 成本式子能写什么

| 写法 | 例子 |
|---|---|
| 尺寸量 | `n(xs)`、`xs.size()`、`n(text)` |
| 阶 | `O(1)`、`O(n)`、`O(log(n))`、`O(n * n)`、`O(n * log(n))`、`O(sqrt(n))` |
| 槽位 | `target { time: { max: … } }`（只写 `max`；单边上界合法） |

**不认的东西**：真指数 `O(2^n)`、`n!`、`α(n)`、跨调用摊还。
不认的时候**明说**（`⊤` 或"无法判定"），不猜。

## 7. 可选：把"选哪个算法"交给测量（`?!`）

有些选择成本模型看不出来（两个候选都是 `O(n)`，谁快取决于规模）。
写两个候选，让运行时按**实测的分档表**挑：

**`pick.tu`**

```elench
error PickError;

spec rank(const vector<u64>& xs) -> u64! {
    effects {};
    benchmodel {
        data { xs = random_u64s(); }
        scale { xs in range(1, 4096, *2); }
    };
    target { time: { max: O(xs.size()) }, allocation: { max: 0 }, };
    choose kernel(const vector<u64>& xs) -> u64! {
        over { by_scan, by_scan_rev };
        objective time;
    };
}
```

**`pick.eln`**

```elench
u64! rank(const vector<u64>& xs) {
    if (xs.empty()) {                 // 宿主必须有自己的逻辑
        return Err(PickError::Empty);
    }
    return ?!kernel(xs);              // 只有这一步未定
} kernels kernel(const vector<u64>& xs) -> u64! {
    by_scan {
        u64 best = 0;
        u64 i = 0;
        while (i < xs.size()) {
            best = max(best, xs.at(i));
            i = i + 1;
        }
        return best;
    }
    by_scan_rev {
        u64 best = 0;
        u64 i = 0;
        while (i < xs.size()) {
            best = max(best, xs.at(xs.size() - 1 - i));
            i = i + 1;
        }
        return best;
    }
}
```

```bash
elench dispatch pick      # 静态判断：要不要测、分几段（只出计划）
elench measure  pick      # 真跑候选，生成 pick.dispatch.yaml（**要提交进版本库**）
elench cost     pick      # 承诺 = 分段上界：每段用该段真会跑的那个候选
```

**三条硬规则**：

- `?!` **不能构成整个函数体**（`E-Choose-WholeBody`）——否则退化成"两套实现二选一"；
- 承诺取**分段上界**：每段用该段实际会跑的那个候选的 `κ`（没有表时退回"所有候选取 max"）；
- 分档表是**实测产物**，可提交、可 diff，**手改无效**。

> `measure` 会按 `.tu` 的 `scale` 造输入；规模太大的样例会撞解释器的步数护栏
> （`elench measure sum` 就撞，加 `--max-size=256` 能过）。

## 8. 常见错误与修法

| 现象 / 诊断码 | 意思 | 怎么改 |
|---|---|---|
| `E-Keyword-Unsupported` | 写了本语言没有的关键字（`class` / `switch` / `try` / `auto` / `new` / `sizeof` / `using`…） | 先试 `--compat`；仍报看消息里给的替代写法 |
| `E-Cast-CStyle` | 写了 `(int)x` 这种 C 风格强转 | 开 `--compat` 即可（等价于 `x as T`）；内建标量以外的类型仍须改写成 `as` |
| `E-Lex-IncludeUnresolved` | include 的头**没找到**（引号形式按包含者所在目录找，尖括号形式按 `ELENCH_INCLUDE_DIRS` 找） | 开 `--compat` 并设对搜索路径；或把库符号写进 `.tu` / 用 `extern … from "lib"` |
| `E-Ai-HasDecl` | `.eln`（实现文件）里出现了**声明**（`struct` / `const` 常量 / 别名） | 开 `--compat`（能降级的会降级）；降不了的把声明挪到 `.tu`——**这是设计边界**，见 §5「已知缺口」 |
| `E-Fn-NoSpec` | `.eln` 里的函数在 `.tu` 没声明（**警告**） | 补 `spec`；整个模块没 `.tu` 时只给一条 `I-Fn-NoSpec-Module` |
| `E-Type-OldName` | 写了 `Option` / `Result` | 改成 `optional` / `expected` |
| `W-Builtin-Deprecated` | 用了 `push` / `length` / `is_empty` | 改成 `push_back` / `size` / `empty` |
| `E-Const-Mutate` | 在 `const` 形参上调用改写方法 | 去掉 `const`，或改成局部变量 |
| `E-Index-OutOfRange` | 下标越界 | 先用 `requires` 或 `i < xs.size()` 保证 |
| `E-Div-ByZero` | 除数是 0（运行期陷阱） | 除前判零，或 `requires b != 0;` |
| `E-Fallible-Missing` | 用了 `?`，返回类型却没写 `!` | 返回类型改成 `T!` |
| `E-Dispatch-NoTable` | 用了 `?!` 却没有分档表 | 先 `elench measure <模块>` |
| `E-Recursion-Unbounded` | 有递归但没写深度 | 补 `recursion depth <= N;` |

**把所有诊断列出来**：`elench check <模块> --format=json`（可 `jq`）。
带 `actions` 的诊断还可以 `--apply=N` 直接取一条修法（改文件的动作只打印 diff）。
