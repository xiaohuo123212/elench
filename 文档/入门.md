# 入门：10 分钟把 Elench 跑起来

> 面向**第一次接触**的人。跟着敲，你会依次看到：**程序跑起来** → **成本上界被算出来**
> → **承诺被打破时构建被拒绝** → **决策点怎么交给测量**。
>
> 不用读规格，不用装依赖（只要 Python ≥ 3.10）。
> 想先知道"这门语言为什么长这样"：读 [介绍](介绍.md)。
> 想搬 C++ 习惯：直接跳 [C++ 程序员上手清单](C++惯用法对照.md)。

---

## 1. 装（1 分钟）

```bash
git clone https://github.com/xiaohuo123212/elench.git
cd elench
python --version            # 需要 3.10+
python src/elench.py        # 不带参数 → 打印用法（19 个子命令）
```

也可以装成命令：

```bash
pip install -e .            # 提供 elench 命令；零第三方依赖
elench --help
```

**不装也行**：本文所有命令里的 `elench` 都可以换成 `python src/elench.py`，效果一样。

## 2. 第一个程序：一个模块两份文件（5 分钟）

Elench 的模块**固定是两份文件**，放同一目录：

| 文件 | 写什么 | 谁写 |
|---|---|---|
| `avg.tu` | **承诺**：签名、`effects`、`target` | 人（AI 提议，人签） |
| `avg.eln` | **实现**：只有函数体，**零声明** | AI / 人 |

**`avg.tu`**

```elench
error AvgError;

spec average(const vector<u64>& xs) -> u64! {
    effects { alloc };
    target { time: { max: O(xs.size()) }, allocation: { max: 0 }, };
}
```

**`avg.eln`**

```elench
u64! average(const vector<u64>& xs) {
    if (xs.empty()) {
        return Err(AvgError::Empty);
    }
    u64 total = 0;
    for (const auto& x : xs) {
        total = total + x;
    }
    return total / xs.size();
}
```

三条命令（`avg` 只写模块名就够，工具自己配 `.tu` + `.eln`）：

```bash
elench check avg      # 语法 / 类型 / 契约
elench cost  avg      # 算 κ，和 target 比
```

`check` 的真实输出（节选）：

```text
✓ 没有诊断

module avg

  ?     average  有体  target  state=?         done / debt 由 elench cost 判定

✓ 通过（1 个函数，其中 0 个无体）
```

`cost` 的真实输出：

```text
module avg

  ✓ average  κ ≤ 10 + n(xs)×7 + 7
             分配 ✓ alloc ≤ 0   (target 0)
             达成：阶够，比值 ≈ 7.00
             副作用：声明 alloc

✓ 所有函数都在 target 之内
```

**`κ ≤ 10 + n(xs)×7 + 7` 怎么读**：`n(xs)` 是 `xs` 的长度；
系数 `7` 是"每轮循环大概花 7 个操作"；`10` 和 `+7` 是循环外的固定开销。
**它比 `target` 里的 `O(n)` 更强**——不只是同阶，连常数都写出来了。

> **`κ` 是什么**：编译器从实现**推导**出的操作数上界。它不需要运行程序。
> 单位是**操作数**，不是时间——所以"κ ≥ 实测操作数"是一条能判真假的命题。

运行程序也不难：

```bash
elench run avg --fn=average --vec=1,2,3    # 打印 2（(1+2+3)/3）
```

> `run` 默认找 `main`；模块里没有 `main` 时用 `--fn=名字` 指定入口。
> `--vec=1,2,3` 给一个 `vector<u64>` 形参，`--u64=5` 给一个标量。

## 3. 让它红：承诺被打破（5 分钟）

把 `avg.tu` 的 `target` 收紧一格（`O(n)` → `O(log n)`），实现一个字不改：

```elench
error AvgError;

spec average(const vector<u64>& xs) -> u64! {
    effects { alloc };
    target { time: { max: O(log(xs.size())) }, allocation: { max: 0 }, };
}
```

```bash
elench cost avg
```

```text
module avg

  ▲ average  κ ≤ 10 + n(xs)×7 + 7
             **超标**：阶不够，比值 ≈ 192414534861.23
```

**`▲` 是债务，不是错误。** 默认口径下 `build` **只记账、不拦截**：

```bash
elench build avg                  # ✓ 通过：记债务，退出码 0
elench build avg --deny-debt      # ✗ 拒绝构建，退出码 1
```

```text
✗ 拒绝构建：1 处超出 target（--deny-debt）：average[time]
```

**为什么默认宽松**：新项目一上来全是债，直接拦会逼所有人去改 `target`——
而"谁写实现谁改目标"正是最该防的作弊。**要门禁就显式加 `--deny-debt`。**

### 三个动词

| 动词 | 命令 | 你得到什么 |
|---|---|---|
| **查** | `elench cost` | κ 的表达式 + 达成 / 债务 / 无法判定 |
| **拒** | `elench build --deny-debt` | 退出码 1：承诺被打破，构建被拒 |
| **修** | 改 `.eln`（换写法 / 换算法）→ 再 `cost` | 比值回到 1.00 左右 |

**全程没有运行被检查的程序**：κ 来自源码结构，不来自测量。

## 4. C++ 写法速成

| 你平时写 | 这里怎么写 | 说明 |
|---|---|---|
| `uint64_t f(const std::vector<uint64_t>& xs)` | `u64 f(const vector<u64>& xs)` | `std::` 前缀也认 |
| （参数）`std::vector<int>& xs` | `vector<u64>& xs` | 可变借用：不拷贝、写得回调用方 |
| （参数）`const std::vector<int>& xs` | `const vector<u64>& xs` | 只读借用；改了报 `E-Const-Mutate` |
| 返回值 `void` / `T` / `T!` | `void` / `T` / `T!` | `T!` = `expected<T, E>` |
| `xs.push_back(v)` / `xs.size()` / `xs.empty()` | 同名 | 旧名 `push` / `length` / `is_empty` 会报弃用警告 |
| `for (const auto& x : xs)` | 同名 | 不拷贝；`auto&` 可改容器元素 |
| `std::optional<T>` | `optional<T>` | `option_some` / `option_none` / `option_unwrap` |
| `throw` / `try` / `catch` | `T!` + `return Err(...)` + `?` | 没有异常 |
| `std::array<T, N>` | `array<T, N>` / `array<T, N>(v)` | 定长；满了再 `push_back` **报错** |
| `s.size()`（字符串） | `s.size()`，但**是字节数** | 要字符数用 `utf8_len(s)` |
| `// O(n log n)` | `.tu` 的 `target` | 这一行会被机器核对 |

**逐条对照（含坑）**：[C++ 程序员上手清单](C++惯用法对照.md)。

## 5. 契约的子句：`.tu` 里能写什么

```elench
// doc-template: 语法模板（name / params 是占位符），不参与编译检查
spec name(params) -> RetType {
    effects { fs, io };                 // 副作用集合；纯函数写 {}
    sizes n = xs.size();                // 给形状量起名（缩写，不是局部变量）
    target {
        time:       { max: O(n) };      // 时间上界（阶）
        allocation: { max: 0 };         // 分配上界：**按字节精确判**
    };
    requires xs.size() > 0;             // 前提：运行期会被检查
    guarantees sorted(ret);             // 语义承诺：可检查的进运行期
    repeats log(n) + 1;                 // 循环圈数上界：运行期会被检查
    recursion depth <= 8;               // 递归深度：**有递归就必须写**
    external { read_file: O(n) };       // 外部调用登记：不登记就按 ⊤
    benchmodel {                        // 测量用的输入规模模型
        data { xs = random_u64s(); }
        scale { xs in range(1, 4096, *2); }
    };
}
```

| 子句 | 一句话 | 违反时 |
|---|---|---|
| `target` | 我承诺的成本上界 | `cost` 判债务 / `build --deny-debt` 拒绝 |
| `effects` | 会不会 IO / 分配 / 改文件 | `E-Effect-Missing` |
| `requires` | 调我的人必须保证的事 | 运行期"前提被违反" |
| `guarantees` | 我保证的事 | 可检查的进运行期，其余给警告 |
| `repeats` | 这个循环最多转几圈 | `E-Repeats-Exceeded` |
| `recursion depth` | 递归最多几层 | `E-Recursion-Depth-Exceeded`；**不写就报 `E-Recursion-Unbounded`** |
| `sizes` | 给形状量起名 | 右侧不是形状量 → `E-Sizes-NotShape` |
| `external` | 外部函数登记成本 | 不登记 → `E-Call-Undeclared` |
| `benchmodel` | 测量时怎么造输入 | 缺了就只能静态判 |

**这些都不是注释**：写了就被核对，而且**总是开**（没有开关）。
理由一句话：**可关掉的断言等于默认关掉的断言。**

### 成本式子能写什么

| 写法 | 例子 |
|---|---|
| 尺寸量 | `n(xs)`、`xs.size()`、`n(text)` |
| 阶 | `O(1)`、`O(n)`、`O(log(n))`、`O(n * n)`、`O(n * log(n))`、`O(sqrt(n))` |
| 槽位 | `target { time: { max: … } }`（只写 `max`；单边上界合法） |

**不认的东西**：真指数 `O(2^n)`、`n!`、`α(n)`、跨调用摊还。
不认的时候**明说**（`⊤` 或"无法判定"），不猜。

## 6. 决策点 `?!`：把"选哪个算法"交给测量

有些选择成本模型看不出来（两个候选都是 `O(n)`，谁快取决于规模）。
写两个候选，让运行时按实测的分档表挑：

**`pick.tu`**

```elench
error PickError;

spec rank(const vector<u64>& xs) -> u64! {
    effects {};
    benchmodel {
        data { xs = random_u64s(); }
        scale { xs in range(1, 4096, *2); }
    };
    target { time: { max: O(xs.size()) }, allocation: { max: 0 }, };
    choose kernel(const vector<u64>& xs) -> u64! {
        over { by_scan, by_scan_rev };
        objective time;
    };
}
```

**`pick.eln`**

```elench
u64! rank(const vector<u64>& xs) {
    if (xs.empty()) {                 // 宿主必须有自己的逻辑
        return Err(PickError::Empty);
    }
    return ?!kernel(xs);              // 只有这一步未定
} kernels kernel(const vector<u64>& xs) -> u64! {
    by_scan {
        u64 best = 0;
        u64 i = 0;
        while (i < xs.size()) {
            best = max(best, xs.at(i));
            i = i + 1;
        }
        return best;
    }
    by_scan_rev {
        u64 best = 0;
        u64 i = 0;
        while (i < xs.size()) {
            best = max(best, xs.at(xs.size() - 1 - i));
            i = i + 1;
        }
        return best;
    }
}
```

```bash
elench dispatch pick      # 静态判断：要不要测、分几段（只出计划）
elench measure  pick      # 真跑候选，生成 pick.dispatch.yaml（**要提交进版本库**）
elench cost     pick      # 承诺 = 分段上界：每段用该段真会跑的那个候选
```

**三条硬规则**：

- `?!` **不能构成整个函数体**（`E-Choose-WholeBody`）——否则退化成"两套实现二选一"；
- 承诺取**分段上界**：每段用该段实际会跑的那个候选的 κ（没有表时退回"所有候选取 max"）；
- 分档表是**实测产物**，可提交、可 diff，**手改无效**。

## 7. 常见错误与修法

| 现象 / 诊断码 | 意思 | 怎么改 |
|---|---|---|
| `E-Func-KeywordRemoved` | 写了 `func f(...) -> T` | 改成 `T f(...)`（`func` / `fn` 已下线） |
| `E-Type-OldName` | 写了 `Option` / `Result` | 改成 `optional` / `expected` |
| `W-Builtin-Deprecated` | 用了 `push` / `length` / `is_empty` / `array<T,N>::filled(v)` | 改成 `push_back` / `size` / `empty` / `array<T,N>(v)` |
| `E-Call-UnknownMethod` | 方法名不存在（如 `pop_back` / `begin`） | 看消息里列出的支持列表 |
| `E-Const-Mutate` | 在 `const` 形参上调用改写方法 | 去掉 `const`，或改成局部变量 |
| `E-Index-OutOfRange` | 下标越界 | 先用 `requires` 或 `i < xs.size()` 保证 |
| `E-Div-ByZero` | 除数是 0（运行期陷阱） | 除前判零，或 `requires b != 0;` |
| `E-Fallible-Missing` | 用了 `?`，返回类型却没写 `!` | 返回类型改成 `T!` |
| `E-Fn-NoSpec` | `.eln` 里的函数在 `.tu` 没声明（**警告**） | 补 `spec`；整个模块没 `.tu` 时只给一条 `I-Fn-NoSpec-Module` |
| `E-Dispatch-NoTable` | 用了 `?!` 却没有分档表 | 先 `elench measure <模块>` |
| `E-Recursion-Unbounded` | 有递归但没写深度 | 补 `recursion depth <= N;` |
| `E-Ai-HasDecl` | `.eln` 里写了 `struct` / `spec` 等声明 | 声明挪到 `.tu` |
| `E-Keyword-Unsupported` | 写了 `class` / `switch` / `try` / `auto` / `new` / `sizeof` … | 消息里带替代写法 |

**把所有诊断列出来**：`elench check <模块> --format=json`（可 `jq`）。
带 `actions` 的诊断还可以 `--apply=N` 直接取一条修法（改文件的动作只打印 diff）。
