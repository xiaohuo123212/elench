# Elench —— 项目介绍

**Elench 是一门面向 AI 代码生成的编程语言。**
它和别的语言只差一句话：**成本是可机检的契约，不是注释。**

> 别的语言让你写「怎么做」；
> Elench 还让你写「要做到什么程度」，然后替你核对。

---

## 一、它解决的两个问题

| # | 问题 | 今天的样子 |
|---|---|---|
| 1 | **AI 写得出来，但核不了** | `// O(n log n)` 只活在注释、PR 描述和作者脑子里，编译器一个都不看 |
| 2 | **常数因子只能靠猜** | 哈希集 / 排序后扫描 / 位图，选哪个取决于输入规模——这件事本来就不可推断，**只能测** |

---

## 二、核心：`target` 与 `κ`

- **`target`**（意图）：人设定、冻结在声明里的上界。
- **`κ`**（事实）：编译器从实现**推导**出的符号化上界。

单位是**操作数**，不是墙钟时间。所以「κ ≥ 实测操作数」是一条能判真假的命题，不是一个估计值。分配单独判，按字节精确计算。

**让 AI 写成本，等于让被考的人自己报分。** 成本由编译器算，这一处谎言就不可能发生。

---

## 三、两种文件

| 文件 | 写什么 | 可撒谎的位置 |
|---|---|---|
| `模块.tu` | 全部声明：签名、`target`、`effects`、`choose` 候选名单、递归深度 | **7 处**（5 不可验证 / 1 部分 / 1 可验证） |
| `模块.eln` | 只有函数体，零声明 | **0 处** |

---

## 四、三个动词

| 动词 | 命令 | 做什么 |
|---|---|---|
| **查** | `elench cost` | 算 κ，与 `target` 比：达成 / 债务 / 无法判定 |
| **拒** | `elench build --deny-debt` | 超出 `target` 就拒绝构建，不让它进产物 |
| **修** | 换候选实现 | 候选写在 `over { … }` 里，由 `?!` 按实测分档表选择 |

---

## 五、决策点 `?!`

```elench
func search(const Vec<u64>& xs, u64 key) -> u64 {
    u64 idx = ?!kernel(xs, key);   // 只有这一步未定
    return idx;
}
```

`?!` 上面挂着 `choose` 的候选名单，**它的成本取所有候选的上界**——想混一个 O(n²) 的候选进来，数学上做不到。运行期按实测生成的分档表切换。

它**不能构成整个函数体**：否则就退化成「两套实现二选一」，生成者不必想清楚算法结构。

---

## 六、诚实边界

- 只做**有界**的成本与效果检查，不做完整程序验证。
- 时间只承诺**量级与结构上界**，不承诺精确耗时。
- 没有代码生成后端；`cpp` 子命令只做语言对照，不是可用后端。
- 实测数据来自**单一规模**（n=16）的一组程序，不是大规模基准。

## 七、快速上手

```bash
pip install .          # 或 ./install.sh（Linux / macOS，无需 sudo）
elench cost   sum      # 只写模块名就够
elench export count    # 静态上界 vs 实测操作数
```

> **术语**：文中说的「成本契约」，学术上的名称是**资源界（resource bound）**。
> Elench 的路线是**声明-核算**（作者写下界，机器核对），
> 与 AARA 一类**推断**路线是取舍关系，不是取代关系。
