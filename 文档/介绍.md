# Elench 介绍：C++ 的形状，可证的语义

> **一句话**：**你已经会的 C++ 习惯，在这里能直接用；换掉的那一层，换成了机器能查的语义。**

这篇文档回答三件事：**它长什么样**（§1）、**它换掉了什么**（§2）、**它的边界在哪**（§3–§5）。
想看代码直接跳 [入门](入门.md)；想搬 C++ 习惯直接跳 [C++ 程序员上手清单](C++惯用法对照.md)。

---

## 0. 它是什么

Elench 是一门**组件语言**：写算法、数据结构这类"有边界、有成本、要被人复用"的零件。

它和 C++ 的关系不是"重做一遍 C++"，而是**两边各取一样**：

| 取什么 | 从哪来 | 为什么 |
|---|---|---|
| **形状** | C++ | AI 与人都熟：`u64 f(const vector<u64>& xs)`、`push_back`、`range-for`、`struct` |
| **语义** | Rust / 值语义 | 拷贝与借用有规则、没有 UB、失败用类型表达、成本可推导 |

一句话记：**语法学 C++（AI 熟），语义学 Rust（可证）。**

## 1. 它长什么样：都是 C++ 的形状

### 1.1 函数

```elench
u64 add_one(const u64& x) {
    return x + 1;
}
```

- **返回类型前置**，C++ 形；`auto add_one(const u64& x) -> u64` 也收。
- **`func` / `fn` 已下线**：写了报 `E-Func-KeywordRemoved`，消息里直接给改法。
- 可能失败写 `u64! f(...)`（$T!$ = `expected<T, E>`），无返回值写 `void f(...)`。
- 形参上：`const vector<u64>& xs` 是**只读借用**，`vector<u64>& xs` 是**可变借用**（不拷贝、写得回调用方）。

### 1.2 类型

| 写什么 | 是什么 |
|---|---|
| `u64` / `u32` / `u16` / `u8` / `i64` / `i32` / `f64` / `bool` | 标量 |
| `vector<T>` / `array<T, N>` / `map<K,V>` / `set<T>` / `stack<T>` / `queue<T>` | 容器 |
| `optional<T>` / `expected<T, E>` | 可空 / 可失败（**只有这两个写法**；`Option` / `Result` 报 `E-Type-OldName`） |
| `struct` / `enum` / `error` | 自定义类型（**只写在 `.tu`**） |
| `T*` / `&x` / `*p` / `p->f` / `nullptr` | 指针（唯一允许别名的地方） |
| `int` / `unsigned` / `long` / `size_t` / `char` / `double` | C++ 拼写，按宽度映射（**`int` 是 64 位**） |
| `std::vector<T>` / `std::string` / `std::optional<T>` … | 与短名**同一个类型** |

### 1.3 语句

```elench
u64 count_above(const vector<u64>& xs, u64 k) {
    u64 n = 0;
    for (const auto& x : xs) {
        if (x > k) {
            n = n + 1;
        }
    }
    for (u64 i = 0; i < xs.size(); i = i + 1) {
        if (xs.at(i) == k) {
            continue;
        }
    }
    return n;
}
```

块一律用 `}` 收尾（没有 `end`），条件必须带括号。`break` / `continue` / `while` / `match` 都在。

### 1.4 容器方法名：就是 C++ 的

| 容器 | 方法 |
|---|---|
| `vector` / `vector<u8>` | `size` `empty` `at` `push_back` `assign` `pop` `find` `insert` `erase` `clear` `back` `front` |
| `array` / `FixedVec` | 同 `vector`，**没有 `assign`**（定长，不能改长度） |
| `map` | `size` `empty` `insert` `put` `get` `contains` `erase` `remove` `clear` `keys` |
| `unordered_map` | `size` `empty` `insert` `get` `contains` `erase` `remove` `clear` `keys` `values`（**没有 `put`**） |
| `set` | `size` `empty` `insert` `contains` `erase` `remove` `clear` `values` |
| `unordered_set` | 同 `set`，另加 `keys`（`keys` 与 `values` 返回同一批元素） |
| `stack` / `queue` | `size` `empty` `push` `enqueue` `pop` `dequeue` `top` `peek` `front` `clear` |

不在表里的名字一律报 `E-Call-UnknownMethod`（消息里会列出该容器支持的名字）。
**`keys()` 只属于 `map` / `unordered_*`，`values()` 只属于 `set` / `unordered_*`**：
`map.values()` 要取"值"请遍历 `(键, 值)` 或 `m.get(k)`；`set.keys()` 不存在——集合里
元素就是键。`unordered_map` / `unordered_set` 的 `keys()` / `values()` 顺序**未指定**
（实现上是插入序，契约不保证），要可复现的顺序请用 `map` / `set`。

**P4-0（2026-11-11）把名字整体对齐了 C++**：`push` → `push_back`、`length` → `size`、
`is_empty` → `empty`，并补上 `find` / `insert` / `erase` / `clear` / `back` / `front`。
旧名还能跑，但 `check` 报 `W-Builtin-Deprecated`（v0.73 移除）。

**但有个别"同名不同义"**——最典型的是 `pop()`：它**返回被弹出的元素**，
而 C++ 的 `pop_back()` 返回 `void`。这类坑集中列在 [C++ 程序员上手清单](C++惯用法对照.md) §2。

## 2. 换掉了什么：把"说不清"变成"可检查"

这一节是这门语言真正的全部内容。七件事，按重要性排。

### 2.1 成本是签名的一部分（`target` 与 `κ`）

```elench
spec sum_all(const vector<u64>& xs) -> u64 {
    effects {};
    target { time: { max: O(xs.size()) }, allocation: { max: 0 }, };
}
```

| 概念 | 谁写 | 是什么 |
|---|---|---|
| `target` | **人** | **意图**：我承诺它不超过这个界 |
| `κ` | **编译器** | **事实**：从实现推导出来的符号上界 |

`elench cost` 把两者比较，只有三种结论：

| 结论 | 含义 |
|---|---|
| **达成** | κ 的阶不高于 target |
| **债务** | κ 超过 target——**记下来，不抹掉** |
| **无法判定** | 推不出上界（记 `⊤`）——**明说，不猜** |

**"不知道"是一等公民。** 这是它和"C++ 里写注释"最根本的区别：注释不会反驳你，κ 会。

口径三条（别读错）：

1. 单位是**操作数**，不是墙钟时间——所以"κ ≥ 实测操作数"是一条能判真假的命题；
2. κ 是**单次调用的最坏上界**，不承诺期望、不承诺跨调用摊还（哈希表一律按 `O(n)` 记）；
3. **上界可以松**：松是安全的，`tools/tightness_compare.py` 会告诉你松在哪、松多少。

### 2.2 没有 UB：每一种"未定义"都有一个明确答案

C++ 里最贵的不是慢，是**"这段代码什么都可能发生"**。这里逐条给了答案：

| 情况 | C++ | Elench |
|---|---|---|
| 无符号溢出 | 回绕 | **回绕**（定义好的） |
| 有符号溢出 | **UB** | **回绕**（定义好的，与 `i8/i16/i32/i64` 位宽一致） |
| 下标越界（`at` / `[]`） | UB | **`E-Index-OutOfRange` 报错** |
| 整数除零 | UB | **`E-Div-ByZero` 运行期陷阱** |
| `back()` / `front()` / `pop()` 在空容器上 | UB | **报错**，并提示先用 `!xs.empty()` 或 `requires` |
| 解引用空指针 | UB | **`E-Pointer-NullDeref`** |
| 忘写 `return` / 类型不匹配 | 编译错或 UB | 编译期报错 |

> **一句话**：**"未定义行为"在这里是"已定义行为 + 一条诊断"。**
> 代价是慢一点（多一次检查），换来的是**成本能算**——算不准的东西没法给上界。

### 2.3 失败用类型表达，不用异常

```elench
u64! checked_sum(const vector<u64>& xs) {
    u64 s = 0;
    for (const auto& x : xs) {
        s = s + x;
    }
    return s;
}

u64! average(const vector<u64>& xs) {
    if (xs.empty()) {
        return Err(CalcError::Empty);
    }
    const u64 total = checked_sum(xs)?;
    return total / xs.size();
}
```

（`CalcError` 在 `.tu` 里声明：`error CalcError;`；`average` 的 `spec` 也在 `.tu` 里。）

- `T!` 就是 `expected<T, E>`；`return x` 就是 `Ok(x)`，写 `return Ok(x)` 反而报错；
- `?` 把失败往上抛；有 `?` 的函数**返回类型必须写 `!`**（`E-Fallible-Missing`）；
- 没有 `try` / `catch` / `throw`——**错误必须在类型里出现**，不能被静默吞掉。

C++ 程序员会立刻问："那我不处理会怎样？"——**编译期就报**，不是运行期崩。

### 2.4 声明就是断言：写了就被查

`.tu` 里的每一条都不是注释，而是**运行期或编译期会被核对**的东西：

| 声明 | 违反时 |
|---|---|
| `requires xs.size() > 0;` | 运行期 `requires 不成立`（前提被违反） |
| `guarantees sorted(ret);` | 可检查的进运行期校验，不可检查的给警告 |
| `repeats log(hi - lo) + 1;` | 循环真跑过这个圈数 → `E-Repeats-Exceeded` |
| `recursion depth <= 8;` | 超过声明层数 → `E-Recursion-Depth-Exceeded`；**不写就报错** `E-Recursion-Unbounded` |
| `effects { io };` | 调了副作用函数却没声明 → `E-Effect-Missing` |
| `target { … }` | 见 §2.1 |

**这条哲学很重要**：**可关掉的断言等于默认关掉的断言**，所以它们**总是开**，没有开关。

### 2.5 声明与实现分家：`.tu` 装承诺，`.eln` 装实现

| 文件 | 谁写 | 内容 | 可撒谎的位置 |
|---|---|---|---|
| `模块.tu` | 人（AI 提议） | 全部声明：签名、`target`、`effects`、`choose` 名单 | **集中在这里**，几十行，人真的会看完 |
| `模块.eln` | AI / 人 | 只有函数体，**零声明** | **0 处**——函数体里没有任何"承诺"可写 |

`.eln` 里出现 `struct` / `spec` 一类声明会报 `E-Ai-HasDecl`：
**可撒谎的东西不许放在实现文件里。**

### 2.6 算法选择外包给测量（`?!` + `choose`）

有些选择**成本模型看不出来**：同样是 `O(n)`，哈希还是排序扫描，取决于输入规模。
这不是"分析不够努力"，是**本来就不可推断**——只能测。

```elench
error CountError;

spec count(const vector<u64>& xs) -> u64! {
    effects { alloc };
    target { time: { max: O(xs.size() * xs.size()) }, allocation: { max: 0 }, };
    choose freq_kernel(const vector<u64>& xs) -> u64! {
        over { freq_pairwise, freq_bucket };
        objective time;
    };
}
```

```elench
u64! count(const vector<u64>& xs) {
    if (xs.empty()) {
        return Err(CountError::Empty);
    }
    return ?!freq_kernel(xs);      // 只有这一步交给测量，其余逻辑照旧
}
```

`?!` 的承诺是**分段上界**：每段取"运行期真会跑的那个候选"的 κ，
分段表由 `elench measure` 实测生成（`<模块>.dispatch.yaml`，可提交、可 diff）。
**跑的不是承诺里那个候选，界就不成立**——所以承诺与运行期必须同源。

`elench cost` 会打印：

```text
?!freq_kernel：静态交点 n=14（freq_pairwise ↔ freq_bucket）
   1–13 → freq_pairwise
   14–1048576 → freq_bucket
```

一条硬规则：**`?!` 不能构成整个函数体**（`E-Choose-WholeBody`）。
否则退化成"两套实现二选一"，作者就不必想清楚算法结构了。

### 2.7 值语义：拷贝是真的，别名只剩指针

```elench
u64 demo_copy() {
    vector<u64> a = {1, 2};
    vector<u64> b = a;        // 拷贝：b 是独立的一份
    b.push_back(3);           // a 还是 {1, 2}，b 是 {1, 2, 3}
    return a.size() + b.size();
}
```

- 赋值 / 传参 / 返回 / 入容器**都拷贝**（七个拷贝点，见 [能力边界](能力边界.md)）；
- `for (auto& x : xs)` 是**引用**（不拷贝，改得动容器），`for (auto x : xs)` 是**按值拷贝**；
- **别名只允许在指针上**：`S* q = &s; q->field = 9;` 改的就是 `s`。

> **诚实边界**：**完整的借用规则（独占 / 共享、NLL）还没落地**。
> 今天能查的是 `const` 形参被改写（`E-Const-Mutate`）与"借用还活着就改"的一部分；
> `f(xs, xs)` 传两个可变别名**现在能过 check**。要不要强制成 Rust 那套是 opt-in 的事，
> 理由与代价见 [为什么界会松](为什么界会松.md) §7.4——**强制会让"改名即用"直接破产**。

## 3. 口径：它到底在算什么

这三条不读懂，会把结论用错。

| 项 | 口径 |
|---|---|
| **单位** | **操作数**（语句、表达式节点、循环圈数），不是时间、不是字节。分配单独按**次数**精确计 |
| **范围** | **单次调用**的最坏上界。**不承诺**期望、**不承诺**跨调用摊还（`α(n)` 在模型外） |
| **方向** | κ 是**上界**，可以松。松不会漏报，只会让你少看见优化机会 |

**为什么不用墙钟**：墙钟取决于机器与负载，同一条命题今天真、明天假，就不是契约了。
操作数只取决于源码结构，任何机器上都同一句话。

**"无法判定"不是失败**：推不出上界时记 `⊤` 并说明原因（树递归、外部调用、
链式指针遍历……），比估一个常数诚实。`build --deny-unknown` 可以在 CI 里把它当红。

## 4. 写不了什么（这一节比"能写什么"更该先看）

### 4.1 有意的缺口（不会补）

| 没有 | 为什么 |
|---|---|
| `class` / 成员函数 / 运算符重载 / 类模板 | 数据与行为分离：`struct` + 自由函数。**这是"像 C 还是像 C++"的那条线**，今天在线的一侧 |
| 迭代器（`begin` / `end` / `*it` / `++it`） | 没有迭代器就没有迭代器失效；`range-for` + 下标覆盖同样的写法 |
| `new` / `delete` / `malloc` / `sizeof` | 与值语义冲突 |
| 宏 / `#include` / 模板元编程 | 与"成本可判定"冲突（`#include` / `#define` 作为 C++ 兼容层被预处理后展开，不是宏系统） |
| `switch` / `goto` / `do-while` / `auto` 局部推断 | 都有明确替代（`match` / 结构化循环 / 显式类型），且替代品**能算成本** |
| 异常 | 失败用 `expected` |
| 真指数 `O(2^n)` 作为 target | 恒真承诺等于没有承诺 |

### 4.2 还没做（可以补）

| 缺口 | 现状 |
|---|---|
| 借用规则完整化 | 只有 `const` 改写与部分冲突检查（§2.7） |
| C++ 后端 | **没有**。`elench cpp` 是最小切片；`elench header` 出带契约注释的 C 头文件 |
| 高阶函数的成本契约 | 按调用点计，泛化形状还没做 |
| `deque<T>` | `check` 直接拒绝（`E-Type-UnimplementedContainer`） |
| 自定义泛型容器 | 只有内建那几种 |

完整清单（含每条实测报错原文）见 [能力边界](能力边界.md)。

## 5. 和其他语言的关系

| 语言 | 它做什么 | 这里不同在哪 |
|---|---|---|
| **C++** | 通用系统语言 | 不追求通用，**不替代 C++**；只借它的形状 |
| **Rust** | 内存安全 + 零开销 | 语义同源（值语义、无 UB、失败用类型），**但多一层成本契约**，且借用规则今天只落了一部分 |
| **Dafny / F\*** | 全功能验证 | 只做**有界**的成本与效果检查，**不做完整程序验证** |
| **Zig** | 显式优于隐式 | 同源，且把"多快"也纳入显式 |

**"像 C++"的决定权在三条硬缺口上**（成员函数、运算符重载、类模板）——它们不补，
"像 C++"就停在"长得像"。这三条都**不在**这个版本的路线里，理由见 [能力边界](能力边界.md) §2.1。

## 6. 与兄弟仓库 `elench-c` 的关系

同一门语言的两个实现，**表面完全一样**：

| | `elench-cpp`（本仓库） | `elench-c` |
|---|---|---|
| 函数声明 | `u64 f(u64 n) { }` | 同 |
| 容器方法 | `push_back` / `size` / `empty` / `find` / `insert` / `erase` / `clear` / `back` / `front` | 同 |
| 类型名 | `optional` / `expected` | 同 |
| 定长数组 | `array<T, N>(v)` | 同 |
| `func` 关键字 | **已下线** | 同 |

`elench-c` 是**受限子集**（写法约束更紧）。**表面一样**是有意的：
同一个 C++ 习惯，两边都不必重新学。

## 7. 现在到哪了（诚实版）

| 项 | 状态 |
|---|---|
| 样例 | **17 对** `.tu` + `.eln`（`文档/样例/`） |
| 子命令 | **19 个** |
| 测试 | **138 个文件**，`python -B tests/runner.py` 一键跑 |
| 实现 | **59 个 Python 文件 / 约 3.6 万行代码**，**零第三方依赖** |
| 契约判定 | 三值（达成 / 债务 / 无法判定），`cost` / `build` / `export` 三条路径共用同一套 κ |
| C++ 后端 | 无（只有最小切片与头文件生成） |

**它不是能用的编译器**：没有完整的静态语义检查，没有后端，性能上比 C++ 慢一个量级
（`能力边界` §3 有 SHA-256 的实测）。它的价值在于：**"成本"这件事第一次能被机器反驳。**
