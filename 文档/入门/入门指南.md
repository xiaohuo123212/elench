# Elench 入门（10 分钟）

> **一句话**：Elench 不证明性能，它**反驳**你写下的性能声明。

学完你会做四件事：**跑一个程序**、**看它的成本上界**、**让它因为超标而拒绝编译**、**给一个决策点配分档表**。

---

## 0. 装

```bash
cd ai-lang-design
pip install -e .          # 提供 elench 命令；零第三方依赖
elench --help
```

**不想装也行**，把 `elench` 换成 `python src/elench.py` 即可，效果一样。

## 1. 第一个程序：两个文件

Elench 的一个模块**固定是两个文件**：`hello.tu`（声明）+ `hello.eln`（实现）。

**`hello.tu`**

```
spec main() -> u64 {
    effects { io };   // 要打印，就得承认
    target { time: { max: O(1) }, allocation: { max: 0 }, };
}
```

**`hello.eln`**

```
func main() -> u64 {
    print("hello, elench");
    return 0;
}
```

**跑起来**：

```bash
elench run hello
# hello, elench
```

退出码 `0`。

> **`print(x)` 是"调试内建"**：成本只记 1 个操作，**不建模 IO 延迟**。
> 真正的 IO 成本属于 `effects { io }` 那一层，是另一件事——
> **别拿 `print` 去测性能**。

---

## 2. 看它的成本上界

```bash
elench cost hello
```

```
module hello
  ✓ main  κ ≤ 2
          达成：阶够
```

`κ` 是**操作数上界**：每条语句 1 次 + 每个表达式节点 1 次 + 每轮循环 1 次。
`target` 是你在 `.tu` 里写的承诺。**两者比的是"阶"，不是倍数**。

---

## 3. 让它因为超标而拒绝编译

**`declare.tu` 里承诺线性，但实现是二次的**：

**`debt.tu`**

```
spec total(const Vec<u64>& xs) -> u64 {
    effects {};
    target { time: { max: O(xs.length()) }, allocation: { max: 0 }, };
}
```

**`debt.eln`**

```
func total(const Vec<u64>& xs) -> u64 {
    u64 s = 0;
    u64 i = 0;
    while (i < xs.length()) {
        u64 j = 0;
        while (j < xs.length()) {
            s = s + xs.at(j);
            j = j + 1;
        }
        i = i + 1;
    }
    return s;
}
```

```bash
elench cost debt
# ▲ 1 个函数超出 target（记为债务，不阻断构建）

elench build debt                 # ✓ 通过——默认只记账
elench build debt --deny-debt
# ✗ 拒绝构建：1 个函数超出 target（--deny-debt）：total
# 退出码 1
```

> **默认"记账不拦截"是刻意的**：新项目一上来全是债，直接拦会逼所有人去改 `target`——
> 而"谁写实现谁改目标"正是最该防的作弊。**要门禁就加 `--deny-debt`。**

> **注意"无法判定"不是"达标"**：若 `target` 里没出现尺寸量（例如 `O(1)`）而 κ 里出现了，
> 检查器会说「无法判定」，并**明确统计**而不是混进"都达标"里。

## 5.（进阶）决策点 `?!` 与分档表

> **模块名就够了**：命令的第一个参数可以是**模块名**（`pick`），
> 不必写全路径——它依次试 `pick`、`pick.tu`、`pick.eln`，最后还会到仓库的
> `文档/样例/` 与 `文档/入门/例子/` 里找。所以在哪个目录下都能跑 `elench parse pick`。

同一个任务写两个候选，让运行时按规模自己挑：

> **承诺取每段最优，不是最差候选。** `cost` 默认按**分段**取上界：
> 每一段用该段最优候选的 κ（没有分档表时用**静态分段**规划）。
> 只有加 `--promise` 时才退回"全候选取 max"的保守界。
> （旧版曾把 max 当默认，两个候选一个是 n 一个是 n² 时 κ 被抬成 n²、判债务；
> 现在默认口径下这个例子是**达成**的——这正是"逐段最优"的意思。）

> **反例图**：`例子/pick-反例-不同阶.svg`（数据在同名 `.csv`）画的正是旧版错误做法——
> 两个候选一个 n、一个 n²，两条线**斜率不同**，承诺被拉到 n²。留作警示，不再作示例。


**`pick.tu`**

```
error PickError;

spec rank(const Vec<u64>& xs) -> u64! {
    effects {};
    benchmodel {
        data { xs = random_u64s(); }
        scale { xs in range(1, 4096, *2); }
    };
    target { time: { max: O(xs.length()) }, allocation: { max: 0 }, };
    choose kernel(const Vec<u64>& xs) -> u64! {
        over { by_scan, by_scan_rev };
        objective time;
    };
}
```

**`pick.eln`**

```
func rank(const Vec<u64>& xs) -> u64! {
    // 宿主必须有自己的逻辑（B-15）
    if (xs.length() == 0) {
        return 0;
    }
    return ?!kernel(xs);
} kernels kernel(const Vec<u64>& xs) -> u64! {
    by_scan {
        u64 best = 0;
        u64 i = 0;
        while (i < xs.length()) {
            best = max(best, xs.at(i));
            i = i + 1;
        }
        return best;
    }
    by_scan_rev {
        u64 best = 0;
        u64 i = 0;
        while (i < xs.length()) {          // 上界必须能静态推出
            best = max(best, xs.at(xs.length() - 1 - i));
            i = i + 1;
        }
        return best;
    }
}
```

```bash
elench dispatch pick      # 静态判断：要不要测、分几段
elench measure pick       # 真跑，生成 pick.dispatch.yaml（**要提交进版本库**）
elench build pick         # 有 ?! 但没表 → 直接失败（E-Dispatch-NoTable）
elench build pick --deny-debt
```

`pick.dispatch.yaml` 长这样：

```yaml
# 由 `elench measure` 生成；MUST NOT 手改。
module: pick
label: kernel
segments:
  - {lo: 1, hi: 12, candidate: by_pairs}
  - {lo: 12, hi: 4096, candidate: by_scan}
```

**运行期真的读它**：`?!kernel(xs)` 按当前 `xs` 的长度查段选候选。

## 5.5 用标准库写个短程序

**`std.tu`**

```
spec main() -> u64 {
    effects {};
    target { time: { max: O(1) }, allocation: { max: 0 }, };
}
```

**`std.eln`**

```
func main() -> u64 {
    FixedVec<u64, 3> xs = FixedVec<u64, 3>::filled(0);
    xs[0] = 3;
    xs[1] = 1;
    xs[2] = 2;
    print(sum_of(xs));
    print(index_of(xs, 1));
    print(is_sorted(xs));
    return 0;
}
```

```bash
elench run std
# 6      ← sum_of
# 1      ← index_of(xs, 1)
# 0      ← is_sorted（3,1,2 不是升序）
```

* 成本：`sum_of` / `index_of` / `is_sorted` 都是 `O(n)`；
* 未找到 → **`len(xs)`**（哨兵）；空输入各有约定（见语法速查 §8.4）。

## 5.55 给程序传输入

`elench run` 支持两种实参：

```bash
elench run std --vec=3,1,2 --u64=1
```

| 写法 | 对应参数类型 |
|---|---|
| `--vec=1,2,3` | `const Vec<u64>& xs`（一个向量） |
| `--u64=5` | `u64 k`（一个标量） |

**按声明顺序取**：参数是向量就吃一个 `--vec`，是标量就吃一个 `--u64`；缺了会直接告诉你缺哪个。

```elench
func main(const Vec<u64>& xs, u64 k) -> u64 {
    print(sum_of(xs));
    return index_of(xs, k);
}
```

```bash
elench run m --vec=3,1,2 --u64=1
# 6
# 退出码 0，返回值 1 被打印在最后
```

## 5.6 并发（`parallel`）

```elench
func f(const Vec<u64>& xs) -> u64 {
    u64 s = 0;
    parallel {
        s = s + sum_of(xs);
        s = s + sum_of(xs);
    }
    return s;
}
```

**v0.71 它按顺序执行**（语义先定，将来换真线程不变）；
**成本 = 各任务之和**（`κ = Σ`），**判阶等价于最慢那个**——所以 `target` 仍然成立，**不需要知道核数**。

## 6. 内建函数一览

| 内建 | 签名 | 成本 | 说明 |
|---|---|---|---|
| `min(a, b)` | `(u64, u64) -> u64` | 1 | 常数成本，可替代 `if` 串两支 |
| `max(a, b)` | `(u64, u64) -> u64` | 1 | 同上 |
| `print(x)` | `(T) -> u64` | 1 + 实参 | **调试用**，不建模 IO |

**内建刻意极少**：**每加一个就是一个新的"可撒谎位置"**，必须证明它「不改变阶」才收。

## 7. 常见错误码

| 错误码 | 意思 | 怎么改 |
|---|---|---|
| `E-Fn-NoSpec` | 有 `func` 没有对应 `spec` | 在 `.tu` 补 `spec` |
| `E-Dispatch-NoTable` | 有 `?!` 但没有分档表 | `elench measure <模块>`，把表提交 |
| `E-Borrow-Conflict` | 借用还活着时改了被借的对象 | 先读完再改，或缩短借用 |
| `E-Lex-StringLiteral` | 本语言**没有字符串字面量** | 用 `Vec<u8>` 表示文本 |
| `E-Target-Thawed` | 达标后又改了 `target` | 别改；要放宽就显式说明 |
| `E-Decl-OldKeyword` | 用了已下线的关键字 | 用 `func` / `const` / `var` |
