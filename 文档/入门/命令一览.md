# 命令一览：`elench` 的每个子命令

> 先看这张表选命令，再看下面每条的开关。
> 所有命令都能只写**模块名**（`elench cost sum` = `sum.tu` + `sum.eln`），也能给路径。
>
> 现有 **19 个子命令**：`run` `check` `parse` `fmt` `highlight` `show` `grammar`
> `cost` `stats` `bench` `export` `effects` `dispatch` `measure` `build`
> `otel` `spec` `header` `cpp`。

## 0. C++ 模式（`--compat`）——**主用法**

把 `.cpp` 改名成 `.eln`（**内容不动**），然后在任意命令后面加 `--compat`：

```bash
elench check 你的文件.eln --compat      # 语法 / 类型
elench cost  你的文件.eln --compat      # κ（没有 .tu 也能算，判决是「未声明契约」）
elench run   你的文件.eln --compat --fn=main
```

**一次设开**，之后不用每条命令都写：

```bash
export ELENCH_COMPAT=1      # Linux / macOS
set ELENCH_COMPAT=1         # Windows cmd
$env:ELENCH_COMPAT = "1"    # Windows PowerShell
```

设开之后 `--no-compat` 可以**临时关掉**（退回严格模式）。

**哪些写法要它、哪些本来就认**：见 [入门 §5 实测矩阵](../入门.md)（逐条实测，
✓/✗ 都带诊断码）。一句话版本：`using` / `typedef` / `auto` / `T{…}` / `static` /
多声明符 / 直接构造 / `static_cast` / 迭代器 `for` / `class` 当 `struct` / `struct` 写在
`.eln` 里 —— 这些要 `--compat`；`int`、`+=`、`xs[i]`、`std::` 前缀、`#include <标准头>`
本来就认。

**它做的**（都是实测：`tests/cases/test_compat_cpp.py` 逐条钉住）：
类成员函数、宏（对象/带参/嵌套/条件编译）、**C 风格标量强转 `(int)x`**
（语义等于 `x as T`）、**`#include "你自己的头"`**（递归内联，头里的函数原型自动翻成
`extern … from "<头>";`，调用能过、κ 里显示 `ext(名字)`）。

**模板（函数模板 + 类模板）**：都在**使用点单态化**——`len(xs)`（`xs: vector<u64>`）
实例化成 `len__u64(const vector<u64>&)`；`Box<u64>` 实例化成 `struct Box__u64`，**成员函数
也跟着实例化**（`P__u64_sum`）。C++ 编译器同样这么做。κ 与手写具体写法**逐字符相同**；
推断不出类型时 `E-Type-InferFailed` 会说清怎么改。

**头文件**：`#include "x.h"` 与 `#include <lib/x.h>` 都在 `--compat` 下**按搜索路径内联**
（尖括号形式要设 `ELENCH_INCLUDE_DIRS`；标准头照旧静默忽略；找不到的头仍然报错）。
`#warning` 在 `--compat` 下跳过。FFI 风格的 `.eln`（`extern … from "lib"`）里 include 只给
C 侧 shim 用，可设 `ELENCH_NO_INCLUDE_INLINE=1` 回到"整行忽略"。

**运算符重载**：`bool operator<(const P&, const P&)` 与成员写法都认；`a < b` 会**改写成**
`P__op_lt(a, b)`，所以 κ 把被调函数的成本算进去（与显式写 `less(a, b)` 逐字符相同）。
认 `== != < <= > >= + - * / []`。

**它不做的**：`P p = P(3)` 这种函数式构造调用、成员默认值 `u64 a = 5;`；
模板只做单态化（无偏特化 / SFINAE / 可变参数 / 非类型参数）。

## 0. 按目的选命令

| 我想…… | 用 |
|---|---|
| 把程序跑起来看结果 | `run` |
| 看它有没有语法/类型/契约问题 | `check` |
| 看它的成本上界 κ 是多少 | `cost` |
| 让它因为超出 target 而拒绝构建 | `build --deny-debt` |
| 看真实跑了多少操作（与 κ 同单位） | `stats --ops` |

| 看 κ 的**形状**对不对（比值随规模平不平） | `export --full` |
| **把成本数据推到本机、看可视化和网页** | `otel` |
| 看 `?!` 该不该测、分几段（可只问一个） | `dispatch` |
| 真的跑候选、生成分档表（可只重测一个 `?!`） | `measure` |
| 格式化代码 / 语法高亮 / 打印 AST | `fmt` / `highlight` / `parse` |

## 1. 检查与查看

```bash
elench run <模块> [--fn=名] [--u64=5] [--vec=1,2,3] [--parallel=threads]
```
执行 `main`（或用 `--fn` 指定函数），打印返回值。参数用 `--u64=` / `--vec=` 传。

```bash
elench check <模块> [--strict] [--format=json|--json] [--apply=N]
```
静态检查：语法 / 类型 / 契约 / 债务。`--strict` 把宽松项（如"while 圈数推不出"）升为错误。

**`--json`（= `--format=json`）：结构化诊断。** stdout 只有一份 JSON（`jq` 直接吃），每条带 `code` / `severity` / `file` / `line` / `col` / `end_line` / `end_col` / `message` / `fix` / `suggestion`。`fix` 是**可直接应用**的替换，`range` 为 1-based 半开区间 `[起行, 起列, 止行, 止列]`：

```json
{"version": 1, "ok": false, "diagnostics": [
  {"code": "E-Logic-WordOp", "severity": "error", "file": "x.eln",
   "line": 2, "col": 13, "end_line": 2, "end_col": 16,
   "message": "……", "fix": {"kind": "replace", "text": "&&",
                             "range": [2, 13, 2, 16]}, "suggestion": null}]}
```

要重构 / 运行期 / 语法错误的诊断 `fix` 为 `null`（消息里仍有改法）；改名类另给 `suggestion`。同一输入两次输出**逐字节相同**（不塞时间戳，`file` 是相对路径）。

**`--apply=N`：取第 N 条修法。** 带 `actions` 的诊断会被编号列出：

```
修法（2 条，`--apply=N` 取一条）：
  1) [E-Guarantee-Uncheckable] 把这行注释掉（`assume` 已移除）    （改文件）
  2) [E-Fn-NoSpec] 在 .tu 末尾插入 spec 骨架                     （改文件）
```

`edit` 类动作**只打印 diff，不落盘**——改动要人确认。

> **为什么重要**：诊断只给散文建议（"请加 `repeats`"）时，读的人还得自己翻译成补丁。
> 结构化之后，agent 可以直接拿 `patch` 去改，这正是"错误必须局部可修"。

```bash
elench parse <文件>
```
打印 AST——调试语法用，给写分析工具的人看。

```bash
elench fmt <文件>... [--check] [--stdout]
```
统一风格。`--check` 只判定不改（CI 用），`--stdout` 打到终端。

```bash
elench highlight <文件> [--tokens]
```
终端里的 ANSI 语法高亮。`--tokens` 打印 token 流。

```bash
elench show <模块.tu> <label>
```
打印某个 `choose` 的声明：候选 / objective / 是否有 pending。

```bash
elench grammar <模块.tu> [--format=ebnf|json|both] [--out=文件]
```
从 `.tu` 导出**受限语法**：EBNF + 词汇表 + 打洞骨架（给生成器用）。

## 2. 成本（核心）

```bash
elench cost <模块> [--json|--yaml] [--variant=max]
```
算 κ 并与 target 比：**达成 / 债务 / 无法判定**。

- 承诺 = **分段上界**：有分档表时逐段取"运行期真跑的那个候选"的 κ；无表退 `max`；
- **越界按「沿最近那段延伸」**：低于声明下界用第一段的候选，高于上界用最后一段的候选
  （以前一律退回"第一个候选"——那是书写顺序，可能恰好是慢的那个）；
- `--variant=max`：强制"所有候选取 max"（消融基线，用来量分段值多少）；
- `--json` / `--yaml`：机读输出（含 `verdict`、`allocation_verdict`）；
  **机读模式下 stdout 只有 JSON**（口径说明等人类可读行会被抑制），可直接 `json.loads()`；
- **`--explain`：给归因**（**达标和超界都输出**）——支配项、**杠杆占比**（"这一项占 κ 的多少"，改占比大的才有效）、元凶行号（带源码片段）、最小修复。
  只读侧表，**不参与任何算术**：开关前后 κ 逐字节相同。
- **`--no-check`：跳过静态检查直接算 κ。** 默认 `cost` 在「有调用既无实现、也无契约」
  （E18：记 1 个操作**不是上界**）时**拒绝出数**（rc=1，并说清"这个 κ 不可信"）。
  真要调试才加 `--no-check`——那时的输出不可信，stderr 会再说一遍。
- **`--diff=<ref>`：与某个 git ref 比。** 比三样：κ 的松紧、**契约本身**
  （target / guarantees / effects / scale）、分档表形状。第二样是关键：
  契约被放松时 **κ 可能一动不动**，只有这里会报 `[放松]`。
  加 `--deny-regress` 可当 CI 门禁。

```bash
elench effects <模块>
```
把每个函数的 κ **按 effect 分列**：按语句切分，归进互斥的桶（纯计算 / 单个 effect / 混合）。
**桶相加 = 函数总 κ**，不重复计数；**只读，不改任何 κ**。

```bash
elench stats <模块> <函数> [--ops]
```
跑一次：调用数 / 分配数 / 迭代数 / 操作数。`--ops` 直接输出操作数 JSON。

```bash
elench bench <模块> <函数>
```
单函数隔离测量：只给判定与比值，不做全量统计。

> 函数体里含 `?!` 时会**拒绝**做隔离测量（拿不到分档表，测出来不代表真实运行），
> 并提示改用 `measure`——它按替换法把整条链路一起测。

```bash
elench export <模块> [--format=table|otlp|svg|csv] [--out=文件] [--function=名] [--timing] [--push]
```
「静态上界 vs 实测」。默认实测 = **操作数**（与 κ 同单位）；`--timing` 改成纳秒
（单位不同，图会各自归一化，只能比增长速度）。

- **`--out=*.otel` / `*.otlp` / `*.otlp.json` 会自动按 OTLP 写**，不必再加 `--format=otlp`；
- `--push` 按 OTLP/HTTP 推出去，端点的配法见 §3。

```bash
elench export <模块> --full [--runs=20] [--sizes=…] [--out=图.svg] [--split]
                          [--max-size=N] [--max-points=N] [--variant=random]
```
**完整报告**：三节文字（上界 / 超额倍数 / 紧度）+ **一个 SVG 文件里六张面板**
（左列时间、右列空间）。`--split` 拆成多个文件；`--variant=random` 跳过最坏搜索
（消融对照臂）。

```bash
elench export <模块|路径> --full [--sizes=16,64,256] [--runs=5] [--out=文件]
                             （格式由 `--out` 后缀决定：`.svg` / `.md` / `.csv` / `.html` / `.otel`） [--out=文件] [--worstcase=文件]
```
**紧度曲线**。出的表：

| 列 | 含义 |
|---|---|
| `κ` | 该规模的静态上界 |
| `ops_typ` | 随机输入的**典型**实测操作数 |
| `slack_typ` | `κ ÷ ops_typ` —— **注意这里叫 slack，不是紧度** |
| `ops_worst` | 用 `worstcase` 搜到的最坏观测值（下界逼近，通常没有） |
| `slack_wc_ub` | `κ ÷ ops_worst`，用最坏观测值当分母 |
| `界成立` | 实测是否仍 ≤ κ |

**怎么读**：看 `slack_typ` **随 n 平不平**，不只看它多大。

| 现象 | 判读 |
|---|---|
| 平坦（比值 ≈ 1） | κ 的阶和真实成本一致，只是常数保守 → **形状对得上** |
| 随 n **上升** | κ 的阶**高**于真实成本 → 界会越来越松（危险） |
| 随 n 下降 | κ 的阶偏低 → 可能上界算漏了 |

> **它不是"紧度"**：随机输入测不到最坏，"κ 压得住"这个结论**偏乐观**；
> 真紧度是 `κ ÷ ops_worst`，需要构造最坏输入（`--worstcase` 读的就是那份数据）。

### 版本对比：`--diff=<ref>`

```bash
elench cost <模块> --diff=HEAD~3        # 加 --deny-regress 可当 CI 门禁
```

比**三样**东西：

| 比什么 | 回答的问题 |
|---|---|
| κ 的变化（L1 阶变 / L3 常数变 / 不变） | 承诺**松紧**变了吗 |
| **契约本身**（target / guarantees / effects / scale） | 承诺**内容**变了吗 |
| 分档表的变化 | 承诺**形状**变了吗 |

**契约那一段是关键**：下面这些改动 **κ 一动不动**，但保证实实在在少了——

```
⚠ 契约变了（target / guarantees / effects / scale；**κ 可能一点不动**）：
  rank   effects      pure              → io              [变化]
  rank   scale        1..4096           → 1..1024         [变化]
  rank   target.time  n(xs)             → n(xs)×n(xs)     [放松]
  ⚠ 有承诺被**削弱或放松**（rank.target.time）：**κ 不会报警**，但你的保证变少了
```

`[放松]` 不是猜的：在几个规模点上比数值，全变大才算放松。

## 3. 观测：推到本机、看可视化和网页

没有 collector、没装 Grafana 时，用这三条就能看见 `export --push` 到底发了什么。

```bash
elench otel sink [--host=127.0.0.1] [--port=4318] [--out=otel.ndjson] [--quiet]
```
起一个**本机 OTLP/HTTP 接收端**（默认 4318），把收到的 metrics/traces/logs 落成 NDJSON。

```bash
elench otel view <otel.ndjson> [--signal=traces|metrics|all] [--slowest]
```
按人看得懂的方式打印：span 按耗时排序、父子缩进成树；metrics 按指标列点。
`--slowest` 只看最慢的几条。

```bash
elench otel dashboard [--file=otel.ndjson] [--port=8080] [--refresh=3]
```
把 NDJSON 画成一张**自刷新网页**（默认每 3 秒），浏览器打开 `http://127.0.0.1:8080`。

**完整一轮**（开两个终端）：

```bash
# 窗口 A：先有东西收
elench otel sink --out otel.ndjson

# 窗口 B：把数据推过去（端点由环境变量给）
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318      # PowerShell: $env:...
elench export sum --push --out=sum.otel

# 回到任意窗口看
elench otel view otel.ndjson
elench otel dashboard --file otel.ndjson --port 8080
```

> 不设端点时 `--push` 会明说 `{'sent': False, 'reason': 'no metrics endpoint'}`，
> 不会假装推成功了。

## 4. 决策点 `?!` 与门禁

```bash
elench dispatch <模块> [<choose名>]
```
三层筛：每个 `?!` 要不要测、分几段。**只出计划，不生成表**。

```bash
elench measure <模块> [<choose名>] [--max-size=N] [--commit]
```
真跑候选，用实测生成分档表（`<模块>.dispatch.yaml`）。
`--max-size` 把表的覆盖范围截到 N（大样例否则会撞解释器的步数护栏）。
**实测**：`文档/样例/sum.tu` 自己的 `scale` 到 4096，直接 `elench measure sum` 会撞
5,000,000 步护栏（rc=1）；`elench measure sum --max-size=256` 就过。

`--commit` 额外写一份**入库参考表** `tables/<模块>.table.yaml`：
新人 clone 下来不必先跑 `measure`（那是分钟级），CI 也能直接跑。
**代价**：交叉点是实测出来的、**与机器有关**，换台机器可能次优——
到底用哪份由 `elench.toml` 的 `[dispatch] source` 决定，见 §9。

```bash
elench build <模块> [--out=路径] [--measure] [--deny-debt] [--deny-unknown]
```
构建门禁：

| 开关 | 行为 |
|---|---|
| （默认） | 只记债务，**退出 0**（渐进采用） |
| `--deny-debt` | 任何维度（time / allocation）超出 target ⇒ **退出 1** |
| `--deny-unknown` | 任何维度"无法判定" ⇒ **退出 1**（CI 用） |
| `--measure` | 构建时真跑测量（慢） |

## 5. 代码生成

### `elench spec <模块>` —— 生成声明草案

给**有实现、没 spec** 的函数输出草案：`effects` 从实现推，**`target` 不生成**
（只给静态 κ 作参考）——从实现推出来的上界会让「实现满足 spec」变成**自证**。

```elench
// foo：target **要你自己定**——从实现推出来的上界等于自证。
// 静态 κ（成本模型算的**上界**，仅供参考）：5
spec foo(vector<u64>& xs) -> u64 {
    effects { };
    // target { time: { max: ??? } };   // ← 填这里
}
```

不填 `target` 的 spec 是**合法的**：`check` 会说「有实现但无 target」，`cost` 会提示还没承诺。

### `elench header` —— C 头文件

```bash
elench header <模块> [--output=x.h]
```
生成 C 头文件：每个函数一行 C 声明，**上面一行注释写着 κ、effects、target**——
契约跟着签名走。别人能编译（拿到签名与契约）。实现用 `elench cpp` 生成，两边的类型来自同一份 `cxx_map`，所以能一起编译链接（2026-11-14 起）。

`<模块>` 只写名字就够（`hello`、`hello.tu`、`文档/入门/例子/hello` 都行）；
老的 `<模块.tu> <模块.eln>` 两个参数写法仍然可用。

```bash
elench cpp <模块> [--output=x.cpp] [--run]
                 [--include=<头>]… [--include-dir=<目录>]…
                 [--link=<.o|.a|.lib>]… [--link-dir=<目录>]… [--lib=<名字>]…
                 [--lib-dir=<目录>]… [--no-static]
```

**不支持的写法**：含 `?!`（决策点）的模块出不了码——实测
`elench cpp sum` / `elench cpp count` 都是 `E-Cxx-Unsupported: 表达式 dispatch 还没支持`。
要出码就在候选里二选一定死，别留 `?!`。

**门前两关**：① 与 `check` / `build` 走**同一条**静态检查（有 error ⇒ rc≠0、**不写文件**）；
② 生成后用真编译器 `-fsyntax-only` 编一遍（编不过 ⇒ rc≠0，**且不落盘**——有旧产物就删掉；
找不到编译器就明确说「跳过」，绝不冒充通过）。编译器用 `ELENCH_CXX` / `ELENCH_GXX` 指定。

**能生成什么**（2026-11-14 实测；语料 19 个模块全部出码 + 编译通过 + 语义与解释器逐字节一致）：

| 层 | 支持 |
|---|---|
| 类型 | `u8/i8/u16/i16/u32/i32/u64/i64/f32/f64/bool`、`vector`/`array`/`map`/`set`/`unordered_map` 任意嵌套、用户 `struct` |
| 语句 | 声明、赋值、复合赋值（10 种）、`while`、三段式 `for`、range-for、`if`/`else if`/`else`、`break`、`continue`、`return`、`block` |
| 表达式 | 四则、比较、逻辑、**位运算**、下标、字段、方法调用（`size`/`push_back`/`at`/`insert`/`keys`/`values`/…）、各种字面量、list-init、struct 字面量、**三目 `? :`**、`print`/`format` |
| 外部库 | `extern "C"` 声明发射、`#include` 注入、链接 `.o`/`.a`/`.lib`、`-L`/`-l` |

**接第三方 C 库**：`.eln` 里写 `extern`（`.tu` 的 `spec … { external "lib"; }` 也认），
生成物顶部会发 `extern "C"` 声明，容器实参在调用点自动补 `reinterpret_cast<const char*>(x.data())`。

```elench
extern XXH64(const vector<u8>& data, u64 len, u64 seed) -> u64 from "xxhash" effects {};
```

| 开关 | 作用 |
|---|---|
| `--include=xxhash.h`（可重复） | 发 `#include "xxhash.h"`；`--include=<xxhash.h>` 发尖括号形式 |
| `--include-dir=<目录>`（可重复） | 只给自检 / `--run` 的编译加 `-I`（生成物里不写路径） |
| `--link=<.o\|.a\|.lib>`（可重复） | 链接时带上 |
| `--link-dir=<目录>` / `--lib=<名字>` | 加 `-L` / `-l<名字>` |
| `--lib-dir=<目录>`（可重复） | **只给解释器侧**：ctypes 找 dll/so 的搜索目录（不进编译命令行） |
| `--no-static` | 关掉 Windows + g++ 默认的 `-static`（默认开：否则生成物离开工具链目录会 `STATUS_DLL_NOT_FOUND`） |

**`--run` 做四件事**：编译 → 链接 → **真跑** → 与 `dsh run` 的 stdout **逐字节比**
（按 `behavior_parity` 口径剥掉末行 main 返回值）。2026-11-14 之前它**只编译、不运行也不比较**。
`--compat` / `--no-check` / `--strict` 会透传给解释器侧。

```bash
# 一条命令：出码 + 编译 + 链接真库 + 运行 + 对拍
elench cpp v.eln --include=cJSON.h --include-dir=path/to/cJSON \
    --run --link=build/cJSON.o --lib-dir=build
#   → ✓ 对拍一致：生成物 stdout 与 `dsh run` 逐字节相同
```

**仍不支持**：`?!`（带 `choose` 的模块报 `E-Cxx-Unsupported: 表达式 dispatch 还没支持`）；
`main` 返回 `vector` / `f64` / struct 会明确拒绝（C++ 入口只能是 `int`，静默截断比报错坏）。

## 5.5 `--compat`：只加拼写，不改语义

**放在任意子命令后面**（`check` / `cost` / `run` / `cpp` …都认）。
它让 `.eln` 接受 C++ 的十种写法，**关掉时行为与以前逐字节相同**——所以它是**方言开关**，不是另一个语言。

| 接受的 C++ 写法 | 降级成 |
|---|---|
| `struct` 写在 `.eln` 里 | 允许（`--strict` 仍拒绝：本语言的分工是"声明在 `.tu`"） |
| `using X = Y;` / `typedef X Y;` / `typedef struct {…} X;` | 别名表 / 同一个 `struct X` |
| `auto x = expr;` | 编译期推断（推不出就报错，不猜） |
| `T{a, b}` / `vector<u64> v{1,2,3}` | 现有构造节点 |
| `f(xs.begin(), xs.end())` | `f(xs)`（只在配平时） |
| `std::vector` / `std::sort` / `std::printf` / `std::min` … | 白名单；表外报 `E-Compat-UnknownStd` |
| 返回类型 `void` | `()` |
| 函数声明开头的 `static` | 跳过 token（局部 `static` 仍拒绝） |
| 多声明符 `u64 a = 1, b = 2;` | 多条声明（AST 与手写多行同形） |
| 直接构造 `u64 x(5)` / `vector<T> v(n, x)` | 单参拷贝初始化 / `filled(x, n)`；没有等价物报 `E-Compat-CtorUnsupported` |

**它做什么 / 不做什么**：

- **做**：让"改个名就能跑"成立 —— `.cpp` 复制成 `.eln` 加 `--compat` 就能 `check` / `cost` / `cpp`。
- **不做**：**不读头文件**。第三方 `#include` 报 `E-Lex-IncludeUnresolved`（标准头白名单静默忽略）；
  库的符号要在 `.tu` 里声明，或写 `extern … from "lib"`。
- **不做**：不改语义。所有降级都是 AST 等价的（`typedef struct` 与手写 `struct` 逐节点相同）。

## 8. 项目配置：`elench.toml`

从**当前目录往上找**第一个 `elench.toml`。目前只有两段：

```toml
[dispatch]
# 用哪份分档表：auto（默认）/ local / repo
source = "auto"
# 入库参考表的目录（默认 tables）
repo_dir = "tables"

[build]
# 缺分档表就直接失败（默认放行）
require_measured = false
```

### `[dispatch] source`：三档，选的是"可复现"还是"本机最优"

| 值 | 用哪份表 | 适合 | 代价 |
|---|---|---|---|
| `local` | `<模块>.dispatch.yaml`（本机测的） | 想要**本机最优** | 新人得自己跑 `measure`；不可复现 |
| `repo` | `tables/<模块>.table.yaml`（入库的） | CI / 新人 clone | 交叉点是**别人机器**上测的，可能次优 |
| `auto`（默认） | 有本机表用本机，否则用仓库表 | 日常开发 | —— |

**为什么必须二选一**：表里存的是实测出来的**交叉点**，那是**机器相关**的。
入库让人少跑一次 `measure`、可复现、可 diff；但换台机器它可能不是最优。
**这两件事没法同时最优**，所以交给你选。

> **没有表时会退回 `max over candidates`**——仍然是个上界，只是更松。
> 所以 `source = "local"` 而本机没测过时，承诺会明显变宽，`cost` 的式子里能直接看出来。
