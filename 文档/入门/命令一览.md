# 命令一览：`elench` 的每个子命令

> 先看这张表选命令，再看下面每条的开关。
> 所有命令都能只写**模块名**（`elench cost sum` = `sum.tu` + `sum.eln`），也能给路径。
>
> 现有 **18 个子命令**：`run` `check` `parse` `fmt` `highlight` `show` `grammar`
> `cost` `stats` `bench` `export` `dispatch` `measure` `build`
> `otel` `header` `cpp`。

## 0. 按目的选命令

| 我想…… | 用 |
|---|---|
| 把程序跑起来看结果 | `run` |
| 看它有没有语法/类型/契约问题 | `check` |
| 看它的成本上界 κ 是多少 | `cost` |
| 让它因为超出 target 而拒绝构建 | `build --deny-debt` |
| 看真实跑了多少操作（与 κ 同单位） | `stats --ops` |
| 看 κ 和实测画在一起 | `export` / `export --full` |
| 看 κ 的**形状**对不对（比值随规模平不平） | `export --full` |
| **把成本数据推到本机、看可视化和网页** | `otel` |
| 看 `?!` 该不该测、分几段（可只问一个） | `dispatch` |
| 真的跑候选、生成分档表（可只重测一个 `?!`） | `measure` |
| 格式化代码 / 语法高亮 / 打印 AST | `fmt` / `highlight` / `parse` |
| 从 `.tu` 导出受限语法骨架 | `grammar` |
| 生成 C 头文件（契约跟着签名走） | `header` |
| 生成 C++ 源码（最小切片） | `cpp` |

## 1. 检查与查看

```bash
elench run <模块> [--fn=名] [--u64=5] [--vec=1,2,3] [--parallel=threads]
```
执行 `main`（或用 `--fn` 指定函数），打印返回值。参数用 `--u64=` / `--vec=` 传。

```bash
elench check <模块> [--strict] [--format=json] [--apply=N]
```
静态检查：语法 / 类型 / 契约 / 债务。`--strict` 把宽松项（如"while 圈数推不出"）升为错误。

**`--apply=N`：取第 N 条修法。** 带 `actions` 的诊断会被编号列出：

```
修法（2 条，`--apply=N` 取一条）：
  1) [E-Guarantee-Uncheckable] 把这行注释掉（`assume` 已移除）    （改文件）
  2) [E-Fn-NoSpec] 在 .tu 末尾插入 spec 骨架                     （改文件）
```

`edit` 类动作**只打印 diff，不落盘**——改动要人确认。

> **为什么重要**：诊断只给散文建议（"请加 `repeats`"）时，读的人还得自己翻译成补丁。
> 结构化之后，agent 可以直接拿 `patch` 去改，这正是"错误必须局部可修"。

```bash
elench parse <文件>
```
打印 AST——调试语法用，给写分析工具的人看。

```bash
elench fmt <文件>... [--check] [--stdout]
```
统一风格。`--check` 只判定不改（CI 用），`--stdout` 打到终端。

```bash
elench highlight <文件> [--tokens]
```
终端里的 ANSI 语法高亮。`--tokens` 打印 token 流。

```bash
elench show <模块.tu> <label>
```
打印某个 `choose` 的声明：候选 / objective / 是否有 pending。

```bash
elench grammar <模块.tu> [--format=ebnf|json|both] [--out=文件]
```
从 `.tu` 导出**受限语法**：EBNF + 词汇表 + 打洞骨架（给生成器用）。

## 2. 成本（核心）

```bash
elench cost <模块> [--json|--yaml] [--variant=max]
```
算 κ 并与 target 比：**达成 / 债务 / 无法判定**。

- 承诺 = **分段上界**：有分档表时逐段取"运行期真跑的那个候选"的 κ；无表退 `max`；
- **越界按「沿最近那段延伸」**：低于声明下界用第一段的候选，高于上界用最后一段的候选
  （以前一律退回"第一个候选"——那是书写顺序，可能恰好是慢的那个）；
- `--variant=max`：强制"所有候选取 max"（消融基线，用来量分段值多少）；
- `--json` / `--yaml`：机读输出（含 `verdict`、`allocation_verdict`）；
  **机读模式下 stdout 只有 JSON**（口径说明等人类可读行会被抑制），可直接 `json.loads()`；
- **`--explain`：给归因**（**达标和超界都输出**）——支配项、**杠杆占比**（"这一项占 κ 的多少"，改占比大的才有效）、元凶行号（带源码片段）、最小修复。
  只读侧表，**不参与任何算术**：开关前后 κ 逐字节相同。
  归因是**只读**的：开关前后 κ 逐字节相同。

```bash
elench stats <模块> <函数> [--ops]
```
跑一次：调用数 / 分配数 / 迭代数 / 操作数。`--ops` 直接输出操作数 JSON。

```bash
elench bench <模块> <函数>
```
单函数隔离测量：只给判定与比值，不做全量统计。

> 函数体里含 `?!` 时会**拒绝**做隔离测量（拿不到分档表，测出来不代表真实运行），
> 并提示改用 `measure`——它按替换法把整条链路一起测。

```bash
elench export <模块> [--format=table|otlp|svg|csv] [--out=文件] [--function=名] [--timing] [--push]
```
「静态上界 vs 实测」。默认实测 = **操作数**（与 κ 同单位）；`--timing` 改成纳秒
（单位不同，图会各自归一化，只能比增长速度）。

- **`--out=*.otel` / `*.otlp` / `*.otlp.json` 会自动按 OTLP 写**，不必再加 `--format=otlp`；
- `--push` 按 OTLP/HTTP 推出去，端点的配法见 §3。

```bash
elench export <模块> --full [--runs=20] [--sizes=…] [--out=图.svg] [--split]
                          [--max-size=N] [--max-points=N] [--variant=random]
```
**完整报告**：三节文字（上界 / 超额倍数 / 紧度）+ **一个 SVG 文件里六张面板**
（左列时间、右列空间）。`--split` 拆成多个文件；`--variant=random` 跳过最坏搜索
（消融对照臂）。

```bash
elench export <模块|路径> --full [--sizes=16,64,256] [--runs=5] [--out=文件]
                             [--format=md|json|csv] [--out=文件] [--worstcase=文件]
```
**紧度曲线**。出的表：

| 列 | 含义 |
|---|---|
| `κ` | 该规模的静态上界 |
| `ops_typ` | 随机输入的**典型**实测操作数 |
| `slack_typ` | `κ ÷ ops_typ` —— **注意这里叫 slack，不是紧度** |
| `ops_worst` | 用 `worstcase` 搜到的最坏观测值（下界逼近，通常没有） |
| `slack_wc_ub` | `κ ÷ ops_worst`，用最坏观测值当分母 |
| `界成立` | 实测是否仍 ≤ κ |

**怎么读**：看 `slack_typ` **随 n 平不平**，不只看它多大。

| 现象 | 判读 |
|---|---|
| 平坦（比值 ≈ 1） | κ 的阶和真实成本一致，只是常数保守 → **形状对得上** |
| 随 n **上升** | κ 的阶**高**于真实成本 → 界会越来越松（危险） |
| 随 n 下降 | κ 的阶偏低 → 可能上界算漏了 |

> **它不是"紧度"**：随机输入测不到最坏，"κ 压得住"这个结论**偏乐观**；
> 真紧度是 `κ ÷ ops_worst`，需要构造最坏输入（`--worstcase` 读的就是那份数据）。

### 版本对比：`--diff=<ref>`

```bash
elench cost <模块> --diff=HEAD~3        # 加 --deny-regress 可当 CI 门禁
```

比**三样**东西：

| 比什么 | 回答的问题 |
|---|---|
| κ 的变化（L1 阶变 / L3 常数变 / 不变） | 承诺**松紧**变了吗 |
| **契约本身**（target / guarantees / effects / scale） | 承诺**内容**变了吗 |
| 分档表的变化 | 承诺**形状**变了吗 |

**契约那一段是关键**：下面这些改动 **κ 一动不动**，但保证实实在在少了——

```
⚠ 契约变了（target / guarantees / effects / scale；**κ 可能一点不动**）：
  rank   effects      pure              → io              [变化]
  rank   scale        1..4096           → 1..1024         [变化]
  rank   target.time  n(xs)             → n(xs)×n(xs)     [放松]
  ⚠ 有承诺被**削弱或放松**（rank.target.time）：**κ 不会报警**，但你的保证变少了
```

`[放松]` 不是猜的：在几个规模点上比数值，全变大才算放松。

## 3. 观测：推到本机、看可视化和网页

没有 collector、没装 Grafana 时，用这三条就能看见 `export --push` 到底发了什么。

```bash
elench otel sink [--host=127.0.0.1] [--port=4318] [--out=otel.ndjson] [--quiet]
```
起一个**本机 OTLP/HTTP 接收端**（默认 4318），把收到的 metrics/traces/logs 落成 NDJSON。

```bash
elench otel view <otel.ndjson> [--signal=traces|metrics|all] [--slowest]
```
按人看得懂的方式打印：span 按耗时排序、父子缩进成树；metrics 按指标列点。
`--slowest` 只看最慢的几条。

```bash
elench otel dashboard [--file=otel.ndjson] [--port=8080] [--refresh=3]
```
把 NDJSON 画成一张**自刷新网页**（默认每 3 秒），浏览器打开 `http://127.0.0.1:8080`。

**完整一轮**（开两个终端）：

```bash
# 窗口 A：先有东西收
elench otel sink --out otel.ndjson

# 窗口 B：把数据推过去（端点由环境变量给）
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318      # PowerShell: $env:...
elench export sum --push --out=sum.otel

# 回到任意窗口看
elench otel view otel.ndjson
elench otel dashboard --file otel.ndjson --port 8080
```

> 不设端点时 `--push` 会明说 `{'sent': False, 'reason': 'no metrics endpoint'}`，
> 不会假装推成功了。

## 4. 决策点 `?!` 与门禁

```bash
elench dispatch <模块> [<choose名>]
```
三层筛：每个 `?!` 要不要测、分几段。**只出计划，不生成表**。

```bash
elench measure <模块> [<choose名>] [--max-size=N] [--commit]
```
真跑候选，用实测生成分档表（`<模块>.dispatch.yaml`）。
`--max-size` 把表的覆盖范围截到 N（大样例否则会撞解释器的步数护栏）。

`--commit` 额外写一份**入库参考表** `tables/<模块>.table.yaml`：
新人 clone 下来不必先跑 `measure`（那是分钟级），CI 也能直接跑。
**代价**：交叉点是实测出来的、**与机器有关**，换台机器可能次优——
到底用哪份由 `elench.toml` 的 `[dispatch] source` 决定，见 §9。

```bash
elench build <模块> [--out=路径] [--measure] [--deny-debt] [--deny-unknown]
```
构建门禁：

| 开关 | 行为 |
|---|---|
| （默认） | 只记债务，**退出 0**（渐进采用） |
| `--deny-debt` | 任何维度（time / allocation）超出 target ⇒ **退出 1** |
| `--deny-unknown` | 任何维度"无法判定" ⇒ **退出 1**（CI 用） |
| `--measure` | 构建时真跑测量（慢） |

## 5. 代码生成

### `elench spec <模块>` —— 生成声明草案

给**有实现、没 spec** 的函数输出草案：`effects` 从实现推，**`target` 不生成**
（只给静态 κ 作参考）——从实现推出来的上界会让「实现满足 spec」变成**自证**。

```elench
// foo：target **要你自己定**——从实现推出来的上界等于自证。
// 静态 κ（成本模型算的**上界**，仅供参考）：5
spec foo(vector<u64>& xs) -> u64 {
    effects { };
    // target { time: { max: ??? } };   // ← 填这里
}
```

不填 `target` 的 spec 是**合法的**：`check` 会说「有实现但无 target」，`cost` 会提示还没承诺。

### `elench header` —— C 头文件

```bash
elench header <模块> [--output=x.h]
```
生成 C 头文件：每个函数一行 C 声明，**上面一行注释写着 κ、effects、target**——
契约跟着签名走。别人能编译（拿到签名与契约），但链接不到实现（实现等 C++ 后端）。

`<模块>` 只写名字就够（`hello`、`hello.tu`、`文档/入门/例子/hello` 都行）；
老的 `<模块.tu> <模块.eln>` 两个参数写法仍然可用。

```bash
elench cpp <模块> [--output=x.cpp] [--run]
```
生成 C++ 源码，**刻意很窄**：参数只支持 `u64` / `i64` / `vector<u64>` / `vector<u8>`；
语句只支持声明、赋值、`while`、`if`、`return`；内建只支持 `sum_of` / `min` / `max`。
其余一律报 `E-Cxx-Unsupported`（明说"没做"，不静默降级）。`--run` 顺便编译运行。

> **目前不支持 `?!`**：带 `choose` 的模块会报
> `E-Cxx-Unsupported: 表达式 dispatch 还没支持`。要试 `cpp`，用不带 `?!` 的模块。

## 7. 环境变量

| 变量 | 作用 |
|---|---|
| `ELENCH_COUNT_OPS=1` | 打开操作数计数（`stats --ops` 会自动开） |
| `ELENCH_STEP_BUDGET=30000000` | 放宽"疑似死循环"护栏（默认 500 万步；大样例会正常超过） |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `export --push` 的通用端点（按信号自动加 `/v1/metrics` 等）；空 = 不推 |
| `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` | 分信号端点，优先于上面那个（`_TRACES_` / `_LOGS_` 同理） |

## 8. 项目配置：`elench.toml`

从**当前目录往上找**第一个 `elench.toml`。目前只有两段：

```toml
[dispatch]
# 用哪份分档表：auto（默认）/ local / repo
source = "auto"
# 入库参考表的目录（默认 tables）
repo_dir = "tables"

[build]
# 缺分档表就直接失败（默认放行）
require_measured = false
```

### `[dispatch] source`：三档，选的是"可复现"还是"本机最优"

| 值 | 用哪份表 | 适合 | 代价 |
|---|---|---|---|
| `local` | `<模块>.dispatch.yaml`（本机测的） | 想要**本机最优** | 新人得自己跑 `measure`；不可复现 |
| `repo` | `tables/<模块>.table.yaml`（入库的） | CI / 新人 clone | 交叉点是**别人机器**上测的，可能次优 |
| `auto`（默认） | 有本机表用本机，否则用仓库表 | 日常开发 | —— |

**为什么必须二选一**：表里存的是实测出来的**交叉点**，那是**机器相关**的。
入库让人少跑一次 `measure`、可复现、可 diff；但换台机器它可能不是最优。
**这两件事没法同时最优**，所以交给你选。

> **没有表时会退回 `max over candidates`**——仍然是个上界，只是更松。
> 所以 `source = "local"` 而本机没测过时，承诺会明显变宽，`cost` 的式子里能直接看出来。

## 9. 四个常见组合

```bash
# 日常：写完代码先看红不红
elench check app && elench cost app

# 发布前：三条门禁一起过
elench build app --deny-debt --deny-unknown
python tools/kappa_vs_ops.py --strict

# 想给某个函数出完整成本图
elench export app --full --runs=20 --out=app.svg

# 想看"成本随规模怎么走"而不是只看一个数
elench otel sink --out otel.ndjson &          # 先起接收端
elench export app --push --out=app.otel
elench otel dashboard --file otel.ndjson
```
