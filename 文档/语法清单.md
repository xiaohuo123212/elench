# 语法清单（一页速查）

> **用途**：写代码时对照；**不是规格**。完整语义见 AI语言设计规格，逐条细节见 语法速查。
> 记号：`[ ]` 可选，`( )` 分组，`…` 重复。

## 1. 文件与模块

| 项 | 写法 | 说明 |
|---|---|---|
| 声明文件 | `*.tu` | **人写、人签**：`spec`、`target`、`effects`、`external` |
| 实现文件 | `*.eln` | **可整份重写**：只有 `func`，**没有声明** |
| 成对规则 | 同名同目录 | `calculator.tu` ↔ `calculator.eln` |
| 引入外部库 | `link "libc";` | 模块级，放在文件顶部 |
| 注释 | `// …` | 行注释；不支持块注释 |

## 2. 声明（只在 `.tu`）

```elench
// doc-template: 语法模板（name / params / RetType 是占位符），不参与编译检查
spec name(params) -> RetType {
    effects { fs, io };                 // 空集合写 {}
    target {
        time:       { max: O(n) };      // 上界（必须单调，且只能收不能放）
        allocation: { max: 0 };         // 分配：**精确**判定
    };
    guarantees { is_sorted(ret) };      // 语义承诺（可检查的进检查器）
      // assume 已移除（2026-11-04）：它允许声明无法验证的上界，与「可验证」冲突
    repeats { log(n) };                 // 算法性质：循环上界
    recursion depth <= 8;               // 递归深度上界（**有递归就必须写**）
    external { read_file: O(n) };       // 外部调用登记
    benchmodel { n = xs.length() };     // 输入规模模型
}
```

| 关键字 | 作用 | 可信位 |
|---|---|---|
| `spec` | 声明一个函数 | — |
| `target` | **成本上界**（time / allocation） | **#2** |
| `effects` | 副作用集合 | **#5** |
| `guarantees` | 语义承诺（**可检查的进运行时校验**，不可检查的报警告） | **#6** |
| `repeats` | 循环次数上界 | **#3** |
| `benchmodel` | 基准的规模模型 | **#7** |
| `external` | 外部调用成本 | **#8** |
| ~~`assume`~~ | **已移除（2026-11-04）**：不可验证的声明，改用真实尺寸 / `benchmodel` 输入 / `external` | — |
| 递归深度 | `recursion depth <= N;` | **#4** |

> **七个可信位 = 2–8**（#1 `cost` 由编译器生成、#9 `??[cost]` 已退休）。

> **递归不是可选项**：函数有递归（直接递归或互递归），`.tu` 却没写
> `recursion depth <= N;` → **编译期报错** `E-Recursion-Unbounded`。
> 理由：不声明深度时 κ 只按**一层**计，会**小于真实成本**——那等于承诺了假话。
> `elench check`、`elench build`、`elench cost`、`elench export` 都会拒绝。

## 3. 类型

| 类别 | 写法 | 备注 |
|---|---|---|
| 整数 | `u64` / `i64` | **二进制补码**：`i64` 有负数（`2-3` = `-1`），`u64` 打印时转回无符号 |
| 浮点 | `f32` / `f64` | `f32` 真按 32 位舍入；`1.0` 是 `f64`；**精确相等不适用于浮点** |
| 布尔 | `bool` | `true` / `false` |
| 字节串 | `vector<u8>` | 字符串就是它 |
| 引用 | `vector<u64>&` | **参数位置**，可变借用 |
| 容器 | `vector<T>` / `map<K,V>` / `set<T>` / `deque<T>` | 方法见 [内建函数](内建函数.md) |
| 可空 | `optional<T>` | `option_some` / `option_none` |
| 结果 | `Result<T,E>` | 错误必须处理或显式忽略 |
| 函数类型 | `func(vector<u64>) -> u64` | **只能出现在参数位置** |
| 枚举 | `enum Json { Null, Num(u64), Arr(vector<Json>) }` | **变体之间用逗号** |
| 结构体 | `struct Entry { key: vector<u8>, value: Json }` | 字段用 `:` |

## 4. 语句

| 语句 | 写法 |
|---|---|
| 常量 | `const u64 n = xs.length();` |
| 变量 | `u64 i = 0;`（**不用 `let`**） |
| 赋值 | `i = i + 1;` |
| 条件 | `if (cond) { … } else { … }` |
| 循环 | `while (cond) { … }` |
| 遍历 | `for (x in xs) { … }` |
| 遍历（带下标） | `for (i, x in xs) { … }` |`i` 是 `u64`，**由语言维护**——写不出 `i <= n` 那种越界；成本与不带下标**结构相同** |
| 遍历映射表 | `for_each(m, f);`（κ = `n(m) × (1 + k(f)) + n(m)`） |
| 匹配 | `match (v) { Num(n) => …, Null => … }` |
| 并行 | `parallel { a(); b(); }`（成本取**和**） |
| 返回 | `return expr;` |
| 跳出 | `break;` / `continue;` |

## 6. 决策点与分档（`?!`）

```elench
spec pick_impl(const vector<u64>& xs) -> u64 {
    target { time: { max: O(xs.length() * log(xs.length())) } };
    // ?! 表示"以下实现都算达标，按实测挑"
}
```

| 步骤 | 命令 |
|---|---|
| 1. 声明候选 | `.tu` 里写 `?!` |
| 2. 实测 | `elench measure` → 生成分档表 |
| 3. 构建 | `elench build`（缺表默认按**静态分段**放行；`--require-measured` 才强制要分档表） |

### 6.1 最小骨架（照 `文档/样例/count.{tu,eln}` 的实际写法）

`.tu` 里三样都要有：**benchmodel**（要测就得说测什么）、**choose**（候选集）、
**target**（承诺）。`choose` **必须写在宿主 spec 块内**，否则报
`E-Choose-NotInSpec`：

```elench
// doc-template: 语法骨架（照 count 样例，非独立可编译模块）
spec pick(const vector<u8>& text) -> u64 {
    effects {};

    benchmodel {
        data  { text = make_texts(); }
        scale { text in range(1, 1048576, *2); }
        seed = 1;
    };

    target { time: { max: O(text.length() * text.length()) } };

    choose freq_kernel(const vector<u8>& text) -> u64 {
        over { freq_bucket, freq_pairwise }
        ;
        objective time;
    };
}
```

`.eln` 里宿主要**有自己的逻辑**（只有 `return ?!…;` 会被 `E-Choose-WholeBody`
拒绝），候选写在函数尾的 `kernels` 块里：

```elench
// doc-template: 语法骨架（同上，靠 kernels 块补实现）
func pick(const vector<u8>& text) -> u64 {
    const u64 len = text.length();
    if (len == 0) {
        return 0;
    }
    return ?!freq_kernel(text);
} kernels freq_kernel(const vector<u8>& text) -> u64 {
    freq_bucket {
        return text.length();
    }
    freq_pairwise {
        return text.length() * text.length();
    }
}
```

跑法：`elench check` → `elench measure`（生成 `*.dispatch.yaml`）→ `elench build`。

> **为什么要写 benchmodel**：`?!` 意味着"按实测挑"，没有数据与规模就没有实测，
> 于是报 `E-Bench-NoModel`。`data` 段写"参数从哪来"，`scale` 段写"测哪些规模"。

## 11. 受限语法与修法（2026-11 新增）

### 从 `.tu` 导出受限语法（给模型做受限解码）

```bash
elench grammar count            # EBNF + 词汇表 + 打洞骨架
elench grammar count --format=json --out=count.grammar.json
```

产物三件：**语言 EBNF**、**模块词汇表**（本模块允许的函数/外部函数/类型/常量）、
**打洞骨架**（每函数一个"签名齐全、body 是洞"的骨架）。
不做完整 AST 的 JSON Schema——那等于重写 parser，两份语法会漂移。

### `guarantees` 怎么写才被检查

```elench
spec f(const vector<u64>& xs) -> u64 {
    effects {};
    guarantees is_sorted(xs);      // 可检查：run 返回后真的求值
    // guarantees ret >= 0;        // 可检查：比较式，ret 是返回值（别名 result）
    // guarantees looks_good(xs);  // ⚠ 不可检查 → E-Guarantee-Uncheckable，请注释掉这行（assume 已移除）
}
```

| 分类 | 后果 |
|---|---|
| 可检查（`is_sorted` / `contains` / 比较式 / 它们的 `&&` `\|\|` `!`） | `check` 报 `I-Guarantee-Runtime`；违反抛 `E-Guarantee-Violated` |
| 不可检查 | `check` 报 `E-Guarantee-Uncheckable`（warning），建议**注释掉**这行 |

### 债务时的修法与两档构建

```bash
elench build m --deny-debt      # CI：有债务就拒绝（退出 1）
elench build m --lenient        # 本地：有债务也放行（退出 0，打醒目提示，不记录）
elench cost m --apply=2         # 执行修法清单里的第 2 条
```

**修法清单里永远不会出现"改 target"**——契约是持久的，实现是一次性的。

### `cost` 里多了一行副作用

```
副作用：声明 fs；调用点 fs×2（read_file）；外部项 ext(read_file)
```

只统计**可指认的**部分：声明了哪些 effect、每个 effect 几处调用点、κ 里有哪些 `ext`。
解释器操作**不按 effect 分摊**（一次操作不属于任何副作用）。

### FFI 调用前会校验参数

`extern` 调用现在先按 `.tu` 签名检查个数/类型/取值：`u64` 传负数直接
`E-FFI-Shape`（以前会静默变成 18446744073709551615）；后端不认识的类型报
`E-FFI-Unsupported`。

### 区间 for、break/continue、`as`、除法（2026-11 起）

```elench
// doc-template: 语法片段（组合示意，不是可编译模块）
for (i in 0..n) { }          // 半开区间 [0, n)；n <= 0 时 0 次
while (…) { if (…) { break; } else { continue; } }   // 只跳出一层
u64 b = 300 as u8;             // 截断成 44（无符号回绕）；i64 按补码
u64 q = a / b;                 // 返回整数；b == 0 → E-Arith-DivZero
```

| 规则 | 说明 |
|---|---|
| 区间 `a..b` | **半开** `[a, b)`；以前这种写法**静默 0 次** |
| `break` / `continue` | 以前查无此关键字（运行期报"未绑定的名字"）；只作用于最近一层循环 |
| `as uN` / `as iN` | 按目标位宽截断；不认识的目标类型直接报错 |
| `/` `%` | 返回**普通整数**（以前返回 `Ok(...)`）；除零由 `requires b != 0;` 负责，运行时抛 `E-Arith-DivZero` |
| 复合赋值 | `+= -= *=` 按 u64 回绕；`/= %=` 除零同样报错 |

## `allocation` 的口径（G33 结论）

**`allocation` 计的是「容器增长事件」的次数，不是字节数。**

- 一个 `vector` 从容量 `c` 涨到 `2c` 记 **1** 次；起始容量是 4，之后翻倍。
- `array<T, N>` 定长，**永远不增长**，所以 `allocation` 恒为 0。
- 切片**不额外分配**：它只是原容器的视图。
- 所以 `allocation: { max: 0 }` 的含义是「这个函数不会让任何容器增长」，
  **不是**「不占内存」。

**为什么不做字节级模型**：字节数取决于元素大小、对齐、分配器策略，
换平台就变，而我们承诺的是**可判定的上界**。次数是确定的，字节不是。
这条是有意的非目标，记在 G33。

## 类型检查的精度边界（E12 结论）

检查器有 `UNKNOWN` 类型，**它与任何类型兼容**；只有两边都确定且不兼容时才报错。

| 会得到 `UNKNOWN` 的情形 | 后果 |
|---|---|
| 泛型参数（`vector<T>` 里的 `T`） | 类型不匹配**查不出来** |
| 闭包 / 高阶内建的返回值 | 同上 |
| 结构体字段的嵌套类型（只到第一层） | 同上 |
| `error X;`（不带变体）的变体 | 任何变体都接受（写了变体就会校验） |

**这是有意的取舍**：宁可漏报，不要误报——`UNKNOWN` 让样例全部能过，
而「确凿的错误」（例如返回 `u64` 的函数写 `return true;`）照样抓住。

**要更精确就得做类型推导**，那是另一个量级的工程；当前定位是「编译器能替人
抓住的、代价低的那一部分错误」。记在 E12。

## 整数溢出：回绕（G35 结论）

**Elench 的整数是固定位宽 + 回绕**，不是任意精度、也不报错：

- `u64` / `i64` 按 `2^位宽` 取模（`interp.py` 的 `_wrap`），`0 - 1` 得 `u64` 的最大值；
- `+ - *` 与一元 `-` 全部走 `_wrap`（v0.67「算术全函数化」）；
- 所以 `target { time: … }` 里的成本**永远是有限数**，不存在「溢出成未知」。

**为什么不选 `Result[T, Arithmetic]`**：那会让每个算术表达式都变成可能失败的操作，
κ 就从「一个式子」变成「一棵 try 树」——成本契约的可读性会被算术错误吞掉。

## 块尾分号：解析器接受，但不强制（E27 结论）

`benchmodel { … }` 与 `choose … { … }` 后面的 `;` **可以写，也可以不写**。

- `fmt` 会统一补上（所以 `fmt --check` 能挡住风格漂移）；
- 解析器用 `accept` 而不是 `expect`——**漏写不报错**。

**为什么没强制**：实测把 4 处 `accept(SEMI)` 改成 `expect` 后，**9 个测试文件、约 30 处内联用例**
全红。收益是「只允许一套写法」，成本是改动面铺到测试集里，而它是 P2（可推后）。
**触发条件**：下次大规模改测试时顺手做，不要为它单独开一轮。

## `spawn` / `asm` / `scope` 已下线（2026-11-05）

三条都曾经「词法认得、EBNF 写着」但**用不了或没用**：

| 关键字 | 原来的状态 | 为什么删 |
|---|---|---|
| `spawn` | **写不出来**（`parse_stmt` 没有分支，报「期望表达式」） | 并发下的时间不是确定上界，取决于核数与调度 → **κ 不再确定** |
| `asm` | **写不出来**（同上） | 内联汇编的操作数不可数 → **「可验证」降级成「可估算」** |
| `scope` | 能解析，但关键字被丢弃（当普通 block） | 存在的唯一意义是给 `spawn` 提供词法边界 |

现在写它们会得到 `E-Spawn-Removed` / `E-Asm-Removed` / `E-Scope-Removed`，各带改法。

**`parallel { }` 保留**：按顺序语义执行、成本保守，是真能用的。

## `unsafe`：现在有两条真规则（2026-11-05）

`unsafe { }` 以前**关键字被丢弃**（当普通块），写了等于没写。现在它有两件事是真的：

| 规则 | 错误码 |
|---|---|
| 函数体里有 `unsafe` 块 → effects 必须声明 `unsafe` | `E-Unsafe-Undeclared` |
| effects 声明了 `unsafe` 但体内没有块（虚报） | `E-Unsafe-Overdeclared` |

**前置也修了**：`EFFECT_VOCAB` 里原来**没有 `unsafe`**，而 `unsafe` 在词法层是关键字，
`effects { unsafe }` 直接报「期望效果名」——一个要求你做不到的事的检查比不检查更糟。
现在效果名允许关键字，词表也收 `unsafe`。

| 调用外部函数（`extern …` 登记的）必须位于 `unsafe { }` 块内 | `E-Unsafe-Required` |

**extern 声明在 `.eln`**，且语法是 `extern f(…) -> T from "lib" effects { … };`
（**没有**外层花括号——写成 `extern … { effects {…} };` 会报 `E-Parse-Expected`，
而且 extern 节点会整个丢掉，这是排查时最容易误判的地方）。

## 高阶函数的成本按**调用点**算（G1 结论）

```elench
func apply(const vector<u64>& xs, func(u64) -> u64 f) -> u64 {
    return f(xs.at(0));          // f 是形参
}
```

`apply` 自己的 κ 里有一项 **`k(f)`**——「f 的成本，待定」。这是诚实的写法，
因为 `apply` 对**所有** f 都得成立。

**以前的问题**：判决那一步把「κ 里没有尺寸量」当成「κ 是常数」，
于是 `… + k(f)` 被判 **✓ 达成**——传进去 O(n²) 的函数也照样说达成。**假上界。**

**现在的两条规则**：

| 规则 | 效果 |
|---|---|
| κ 里出现未解释符号（`k(f)`） → 判 **unknown** | 不给假 ✓ |
| 被调函数的 target 建立在 `k(f)` 上 → **调用方不许信任它**，退回内联 | 内联时形参绑到实参的具名函数 |

于是：

| 调用 | 结果 |
|---|---|
| `apply(xs, sq)`（sq 是 O(n²)） | κ 里出现平方项 → `unknown`（真的算出贵） |
| `apply(xs, one)`（one 是 O(1)） | κ 是常数 13 → ✓ 达成 |
| `apply(xs, xs.at(0))`（实参不是函数名） | `k(f)` 保留 → `unknown` |

**代价**：`apply` 自己永远是 `unknown`（它的契约确实算不出）；判在工作**调用点**做。

### 数值语义（2026-11-05）

- **整数是二进制补码**：`i64 d = 2 - 3;` → `d == -1`。`u64` 的值在打印时按声明类型转回无符号。
- **除法向零截断**（C++ 语义）：`-7 / 2 == -3`，`-7 % 2 == -1`。
- **整数除零是错误**（`E-Arith-DivZero`，用 `requires b != 0;` 约束）；`/` `%` 的类型是 `Result<_, Arithmetic>`。
- **浮点除零是 IEEE 结果**：`1.0 / 0.0 == inf`、`0.0 / 0.0 == nan`，**不是错误**，所以浮点除不返回 `Result`。
- **`f32` 真按 32 位舍入**：`f32 a = 0.1; f64 b = a;` 得 `0.10000000149011612`。
- **浮点不要用 `==` 判等**：`guarantees` 里涉及浮点的比较必须写容差，否则同值不同编译器会判错。

## 资源释放（B0，2026-11-05）

**语言不提供析构函数，也不暴露 `new` / `delete`。资源在作用域结束时释放。**

```elench
// doc-template: 示意"作用域结束即释放"，不参与编译检查（`...` 不是语法）
func f() -> u64 {
    vector<u64> tmp = ...;      // 分配
    return 0;                // ← tmp 在这里释放（作用域结束）
}
```

| 前提 | 由谁保证 |
|---|---|
| 没有裸指针 / `new` / `delete` | 语言里根本没有这些关键字 |
| 引用不会活过被引用对象 | 借用检查（BR-1 / BR-2 / BR-4） |
| **没有循环引用** | **BR-5：结构体不得存引用** |

第三条是关键：结构体里不能放引用 ⇒ 造不出环 ⇒ **引用计数或作用域释放都够用，不需要 GC**。
生成 C++ 时由 `std::vector` 的析构函数完成，**语言层零语法**，也不需要 `drop(x)`。

**已知限制**：解释器靠 Python GC 回收 ⇒ `allocation`（次数）不受影响，
但「峰值」测不准（这是 G8 挂起的隐藏理由之一）。

### 内建 `swap`（B3，2026-11-05）

```elench
// doc-template: 示意用法，不参与编译检查（xs 是上下文里的容器）
swap(xs, i, j);      // 原地交换，O(1)、不分配、返回 u64(0)
```

**下标越界直接报错**（不是静默）。它是**原语**，不保证任何不变量——
就像 `sort(xs)` 之后你再 `push` 就不有序了，堆序也要调用者自己维护。

### `optional` 的取值（E2，2026-11-05）

```elench
// doc-template: 示意三个取值函数，不参与编译检查（o 是上下文里的 optional）
```

## 容器支持现状（B2，2026-11-05）

| 容器 | 状态 | 成本口径 |
|---|---|---|
| `vector<T>` | ✅ 可用 | 增长按次数计 |
| `array<T, N>` | ✅ 可用（定容，溢出报错） | 0 分配 |
| `optional<T>` | ✅ 可用（`option_is_some` / `option_unwrap` / `option_unwrap_or`） | O(1) |
| `Result`（`T!`） | ✅ 可用（`Ok` / `Err`） | O(1) |
| `map<K,V>` | ✅ **可用**（有序，键序迭代） | 查找/插入 **O(log n) 确定** |
| `set<T>` | ✅ **可用**（有序，元素序迭代） | 同上 |
| `deque<T>` | ❌ 未实现（用 `vector` + 两索引即可） | — |
| `heap` / `stack` / `queue` | ⬜ 未提供 | 用 `vector` + `swap` / `push_heap` 原语表达 |

### 为什么 `map` / `set` 没有直接给

**不是没时间，是成本口径要先定：**

- **哈希表**：查找**最坏 O(n)**（碰撞、对抗输入），顺序**不可复现**，键要哈希 + 相等；
- **红黑树**：查找 **O(log n) 确定**，顺序 = 键序，键只要全序。

**两种都能写进契约，但语义完全不同**，选错会让「上界」变成「平均值」——
那正是 G1 修掉的那类问题。**先定语义，再实现，顺序不能反。**

**当前可用替代**：

| 想要 | 怎么写 | 成本 |
|---|---|---|
| 键在小整数区间 | 直接用 `vector<T>` 做直接寻址（下标 = 键） | **O(1) 精确** |
| 任意键 | 排序 + 二分 | **O(log n) 确定** |
| 栈 | `vector` 的 `push` / `pop` | O(1) |
| 队 | `vector` + 两个索引 | O(1) |
| 优先队列 | `swap` + 手写上浮下沉 | O(log n) |

### `stack<T>` / `queue<T>`（薄封装）

```elench
// doc-template: 示意接口，不参与编译检查
stack<u64> st = stack<u64>::new();
st.push(1);  u64 a = st.top();  u64 b = st.pop();

queue<u64> qq = queue<u64>::new();
qq.push(1);  u64 f = qq.front(); u64 g = qq.pop();
```

| 项 | 说明 |
|---|---|
| 成本 | 全部 **O(1)**（queue 的 pop 用读游标摊销） |
| 空容器 pop | **报错**，不静默 |
| 为什么是"适配器" | C++ 的 `stack`/`queue` 也是容器适配器（默认包 `deque`），不是容器 |

### `unordered_map<K,V>` / `unordered_set<T>`

```elench
// doc-template: 示意接口，不参与编译检查（t 是上下文里的容器）
unordered_map<u64, u64> t = unordered_map<u64, u64>::new();
t.insert(3, 30);  u64 v = t.get(3);  t.contains(3);  t.remove(3);
```

| 项 | `map` / `set`（有序） | `unordered_map` / `unordered_set` |
|---|---|---|
| 查找/插入/删除 | **O(log n)** | **O(n)**（承诺最坏） |
| 迭代顺序 | 键序，**可复现** | **未指定——不要依赖** |
| 键的要求 | 全序 | 哈希 + 相等 |

**`unordered_*` 在我们的模型里每一项都比 `map` 差**（O(n) vs O(log n)）。
它存在的意义是**与 C++ 对齐**，不是更快——**别指望它快**。

顺序**不保证**，所以任何"按顺序输出"的用例都不能用它。

### FFI 形状校验：三类各查到什么程度

调用 `extern` 前，实参按 **`.tu` 声明的类型**检查（`shape.validate`，与后端无关）：

| 类 | 覆盖 | 说明 |
|---|---|---|
| **个数** | ✅ | 少给或多给 → `E-FFI-Shape` |
| **类型** | ✅ | `vector<u8>` 收字节串/整数列表；`u64` 收非负整数并查上界；`i64`/`bool`/`f32`/`f64` 各查 |
| **长度** | ✅ **仅定容 `array<T, N>`** | 声明里有 N，可静态查；**`vector<T>` 没有声明长度 → 查不了** |

**两个错误码必须分开**：

| 码 | 含义 | 谁来修 |
|---|---|---|
| `E-FFI-Shape` | **调用者写错了**（个数/类型/取值/长度） | 改调用点 |
| `E-FFI-Unsupported` | **后端不认识这个类型**（不是写错） | 换类型或换后端 |

混在一起，人会去改一个没写错的调用。

**边界（写清楚，免得误解）**：`vector<T>` 的长度**没有契约**，所以**不做**长度校验——
要长度约束就写 `array<T, N>`。

### 门禁是全函数：`unknown` 不等于放行

`build --deny-debt` 遇到 **`unknown`**（κ = ⊤、循环上界推不出）也**拒绝**：

| 情形 | 退出码 |
|---|---|
| 超出 target（debt） | 1 |
| **无法判定（unknown）** | **1**（2026-11-06 起；以前是 0，只打印提示） |
| 不带任何开关 | **0**（渐进采用不变） |

**为什么必须这样**：`unknown` 被当成"没问题"，等于上界语言最大的失败模式——
"我不知道"和"我保证"在退出码上不能同形。

### 分配维度的比较语义（和 `time` 不同）

| 维度 | 人写的是 | 比较方式 |
|---|---|---|
| `time` | `max: O(n)` —— 一个**阶** | **按阶** |
| `allocation` | `max: 0` / `max: 1` —— 一个**数** | **按数值** |

`allocation` 的三条规则：

| 情形 | 判法 |
|---|---|
| 两边都是常数 | **数值比**（`impl ≤ target` 才算达成） |
| target 是常数、impl 带符号 | **债务**（承诺 0 次、实际每轮 1 次——规模一大必然超） |
| 其它（target 带符号） | 退回**按阶** |

**两个容易踩的点**：

1. **`allocation: { max: O(1) }` 被当成常数 `1`** —— 写 `O(1)` 和写 `1` 等价，
   于是"每轮分配一次"直接判**债务**。这一维上 `O(1)` 不是"常数阶"，是"1 次"。
2. **`target = 0` 时比值无意义**（分母为 0），报表里该格会空着。

**为什么不像 time 那样一律按阶**：`max: 0` 和 `max: 1` 在阶上都是 `O(1)`，
按阶比会让"承诺不分配、实际每轮分配"**静默通过**——那正是 E36/H1 消灭的洞。

## `cost diff` 的分级（L1 / L2 / L3）

> 2026-11-06（L-09）。分类只看**数值曲线**，不看表达式文本。

| 档 | 含义 | 判据 |
|---|---|---|
| **不变** | 曲线完全一致 | 比值恒为 1 |
| **L3** | 同阶，**整体乘了一个常数** | 各规模比值恒定（≠1） |

## 效果 `panic`

> 2026-11-06（L-05）。

**会 panic 的内建**：`unwrap` / `expect` / `panic` / `assert` / `assert_eq`。

`effects { }` 的函数里调用它们 → `E-Effect-Missing`（带行号）。
要老实声明就写 `effects { panic }`——`panic` 在效果词表里。

**为什么以前是坏的**：`EFFECT_VOCAB` 里没有 `panic`，写了反被 `E-Effect-Unknown` 拒；
而 `stdlib.EFFECTS` 里也没有映射，所以不写又一声不响。
**双重失效**：既不能声明，也不会报错。

## `cost --explain` 的「余量」

> 2026-11-06（L-08）。回答"还差多少就超了"。

| 情形 | 输出 |
|---|---|
| 两边都是数（如 allocation `max: 0`，实际 0） | `余量 0（target 0 − 实际 0，alloc）` |
| 实际超过 target | `超支 1（target 0 − 实际 1，alloc）` |

## `κ` 的口径：**对终止执行的**上界

> 2026-11-06 确立。

`κ` 界的是**会终止的那些执行**——不终止的执行没有成本，也就不需要上界。

这条不是补丁，是**部分正确性**的标准口径。它带来三个直接后果：

| 场景 | 结论 |
|---|---|
| 环形计数器 `i = (i + 1) % len` | 圈数 ≤ len，**不需要**"表里必有空槽"这种前提 |
| 死循环 | 没有终止执行 ⇒ 任何界都成立 ⇒ 不因为它"便宜"而放行 |
| 循环上界推不出 | 仍是 `⊤`（不知道），**不是**"成本为 0" |

**与"不给假上界"的关系**：口径只放宽"不终止"这一种情况，
**不放宽"算错了"**——算错仍是错，见 `工具/对抗语料` 里的假上界反例。

## `target` 的槽位：**单边上界合法**

> 2026-11-06 决定（不引入 `E-Cost-UpperOnly`）。

```text
target { time: { max: O(n) } }        // ✅ 合法：只写上界（片段，不是完整函数）
```

**只有上界没有下界是正常的**——本语言承诺的是**上界**，不是"恰好"。
`max_in` 这种函数的下界取决于输入分布，**作者写不出来**；强制要求只会逼出凑数的 `min`。

**不做的另一面**：因此也**不检查**"target 写得过松"。紧度由作者负责，
工具只回答"实现是否在上界之内"。

## `?!` 分段（piecewise）的**边界取值**

> 2026-11-07（L-10）。以前文档只写"越界按回退"，**边界点取哪一段没写**。

| 规则 | 说法 |
|---|---|
| 区间 | **闭区间** `[lo, hi]`，两端都含 |
| 取值 | 按**整数**选区（`lo - 1` / `hi + 1` 作哨兵，见 `PIECE_BIG`） |
| 重叠 | **先匹配先赢**——所以构造方必须让段不重叠（用 `lo-1` / `hi+1`） |
| 越界 | 用 `Cost.piece` 的 `args[0]` 回退，**不静默钉一个常数** |

**为什么"先匹配先赢"要明说**：两段相邻时（`[0,16]` 与 `[16,64]`），`n=16`
会**同时命中**——不写清楚，读的人会以为取后一段。

## `export` 的图与表：**图是示意，表是证据**

> 2026-11-07（T-10）。这条是**口径声明**，不是格式说明。

`elench export --full` 会出**图**（`.svg`）和**表**（`--format=csv`）。两者**不等价**：

| | 能否复算 | 能否进 CI | 用途 |
|---|---|---|---|
| **表**（`--format=csv`） | ✅ 重跑得同一组数 | ✅ | **证据**——引用数字请引表 |
| **图**（`--out=x.svg`） | ❌ 没人核对像素 | ❌ | **示意**——给人看形状，**不作契约** |

图里第一面板是「上界与实测」：`target`（阶承诺）、`承诺`（候选取最大）、`典型实测`
**画在同一纵轴上**。这是**学校/演示场景**的读法——**正文里禁止把图上的相对位置当结论**，
要说得清就去引表里的数。

**为什么写这句**：图的纵轴是**对数刻度**，两条线看着"贴在一起"可能差好几倍；
而表里每一格都是能重跑出来的数。
