## 1. 文件形态：`.tu` 与 `.eln`

| 文件 | 只能放 | 不能放 |
|---|---|---|
| `.tu` | `error` / `struct` / `enum` / `const` / `spec` / `link` / 顶层 `external { … };` / `use` | **函数体** |
| `.eln` | 函数体（C++ 形状 `T f(…) { … }`）+ `kernels` | **任何声明**（`.eln` 里写 `enum` → `E-Ai-HasDecl` rc=1） |

配对规则：同名同目录（`count_above.tu` ↔ `count_above.eln`）。两边都写了才叫"有契约"：

- `.eln` 有函数、`.tu` 没有 `spec` → **警告** `E-Fn-NoSpec`（不阻断；`--strict` 才判成 error）。
- 整个模块没有 `.tu` → 一条 `I-Fn-NoSpec-Module` 提示，不逐条报。

```elench
// 只写模块名就自动找 .tu / .eln —— 这对文件真的跑过（check / cost / run 三个都 rc=0）
// count_above.tu
error CountError;

spec count_above(const vector<u64>& xs) -> u64 {
    effects {};
    target { time: { max: O(xs.size()) }, allocation: { max: 0 }, };
}
```

```elench
// count_above.eln —— 函数体这边只写 C++ 形状
pub u64 count_above(const vector<u64>& xs) {
    u64 n = xs.size();
    u64 c = 0;
    u64 i = 0;
    while (i < n) {
        if (xs[i] > 100) { c = c + 1; }
        i = i + 1;
    }
    return c;
}
```

**注释只有 `//`**（`///` 是文档注释）；`/* … */` 报 `E-Lex-BlockCommentUnterminated`（rc=1）。
**预处理**：`#include` 的**标准头**（138 项白名单）与 `#pragma` 丢弃；**非标准头报 `E-Lex-IncludeUnresolved`**（我们不读头文件，第三方库的符号要用 `.tu` 声明）；`#define` 展开后再分析，`#error` 报 `E-Lex-PreprocessorError`。

## 2. 函数与声明

### 2.1 唯一形状：返回类型前置（`func` / `fn` 都已下线）

```elench
u64 add_one(u64 x) {
    return x + 1;
}

// 后置返回也收（同样是 C++ 形状）
auto add_one2(u64 x) -> u64 {
    return x + 1;
}

// 没有返回值
void bump(vector<u64>& xs) {
    xs.push_back(1);
}

// 可能失败：返回类型写 `T!`
u64! maybe(u64 x) {
    if (x == 0) { return Err(CountError::Empty); }
    return x;
}
```

```text
func f(u64 x) -> u64 { }     // ✗ E-Func-KeywordRemoved（rc=1）
fn   f(u64 x) -> u64 { }     // ✗ E-Func-KeywordRemoved（rc=1）
```

### 2.2 `void` 的两种拼写必须两边一致

| 写法 | `.tu` | `.eln` | rc |
|---|---|---|---|
| 推荐 | `-> void` | `void f(…)` | 0 |
| 也收 | `-> ()` | `() f(…)` | 0 |
| **混写** | `-> ()` | `void f(…)` | **1**（`E-Spec-SigMismatch`：`.tu=()` vs `.ai=void`） |

`--compat` 下 `void` 与 `()` 互相映射（两种混写都 rc=0），但**别依赖它**：默认路径是"拼写要一致"。

### 2.3 形参：值 / 借用

| 写法 | 含义 | 失败写法 |
|---|---|---|
| `u64 x`、`vector<u64> xs` | 传值（拷贝） | — |
| `vector<u64>& xs` | **可变借用**：不拷贝，改得动调用方的容器/结构体 | 标量 `u64& x` → `E-Ref-Scalar`（写不回调用方） |
| `const vector<u64>& xs` | **只读借用** | 在里面改 → `E-Const-Mutate` |

- **引用只出现在形参位置**：局部写 `vector<u64>& r = xs;` 报 `E-Ref-Local`（rc=1）——它只会得到一份拷贝。
- `const` **不做类型推断**：`const idx = 5;` 报 `E-Decl-ConstNoType`（rc=1），必须 `const u64 idx = 5;`。
- 形参顺序两种都吃得下（`u64 x` 与 `x: u64` 解析成同一个 AST），**统一写 `u64 x`**。

### 2.4 递归必须声明深度（**运行期真的会查**）

```elench
// .tu
spec fact(u64 n) -> u64 {
    effects {};
    recursion depth <= 8;
    target { time: { max: O(n) }, allocation: { max: 0 }, };
}
```

| 情形 | 结果 |
|---|---|
| 有递归、`.tu` 没写 `recursion depth` | `E-Recursion-Unbounded` rc=1 |
| `recursion depth <= 0` / `<= n`（读不出正整数） | `E-Recursion-BadDepth` rc=1 |
| 声明 8 却真跑到第 9 层 | **运行期** `E-Recursion-Depth-Exceeded` rc=1（`fact(5)` rc=0、`fact(9)` rc=1） |

### 2.5 关键字表（`src/lexer.py:KEYWORDS`，实测 37 项；其中 `eof` / `ident` 是占位 token 种类，**语言关键字 35 个**）

```text
as  asm  assume  break  choose  const  continue  dyn  else  enum  error
extern  external  false  for  func  ident  if  impl  in  kernels  match
parallel  pub  return  rewrite  scope  self  spec  spawn  struct  trait
true  unsafe  use  while  eof
```

- **保留字不能当标识符**：把函数命名成 `use` 会解析失败（`spec use() -> u64` → `E-Parse-Expected`）。
- 已下线但仍留在词表里的：`func` / `val` / `var` / `let` / `end` / `and` / `or` / `not`
  （`REMOVED_KEYWORDS`；写出来给对应的 `E-*`，不是静默当标识符）。
- `spawn` / `asm` / `scope` 仍是关键字但**已下线**；`assume` 已移除。

## 3. 类型

| 类别 | 写法 | 实测备注 |
|---|---|---|
| 整数 | `u8 u16 u32 u64`（无符号）/ `i8 i16 i32 i64`（补码） | 表达式内部保持无符号语义 |
| 浮点 | `f32 f64` | `1.0` 是 `f64`；浮点**精确相等不可靠**：`0.1 + 0.2 == 0.3` 打印 `ne` |
| 布尔 | `bool`（`true` / `false`） | **与整数不互通**：`bool b = 1;` → `E-Type-Assign` rc=1 |
| 字节串 | `vector<u8>`（字符串字面量就是它） | `"n ="` 分配 **0**（静态段），成本 1 个操作 |
| 容器 | `vector<T>` / `array<T, N>` / `map<K,V>` / `set<T>` / `unordered_map<K,V>` / `unordered_set<T>` / `stack<T>` / `queue<T>` | 方法见 §7.3 |
| 可空 | `optional<T>`（`option_some` / `option_none` / `option_unwrap_or`） | **没有容器方法**：`o.is_some()` → `E-Type-OptionToScalar` |
| 结果 | `expected<T, E>`，返回类型位置可写 `T!` | `return x` 就是 `Ok(x)`（见 §4） |
| 元组 | `(A, B)`（≤3），字段 `.0` / `.1` | `(u64, u64) p = (1, 2); print(p.0);` rc=0 |
| 结构体 | `struct Entry { key: vector<u8>, value: u64 }` | 字段用 `:`；字面量见 §5 |
| 枚举 | `enum Json { Null, Num(u64), Str(vector<u8>) }` | 变体之间**逗号**；载荷**单个** |
| 引用 | `T&` / `const T&` | **只在形参位置** |
| 指针 | `u64 * p = &x;` / `*p` / `p->f` / `nullptr` | rc=0；解引用确定的 `nullptr` → `E-Pointer-NullDeref`（静态就报） |
| 函数类型 | `func(vector<u64>) -> u64` | **只能出现在参数位置** |
| 旧别名 | `Vec<T>` ≡ `vector<T>`、`FixedVec<T,N>` ≡ `array<T,N>` | 不报错（`typenames.CANON`），但新代码别写 |
| 不存在的类型名 | `Result` / `Deque` / `deque` / `Split` / `split` / `auto` | 各自报 `E-Type-OldName` / `E-Type-UnimplementedContainer` / `E-Type-Unknown` / `E-Keyword-Unsupported` |

### 3.1 嵌套容器：**三层也能跑**（旧稿说"只支持一层"）

```elench
u64 nested(vector<vector<vector<u8>>> rows) {
    return rows.size();
}
```

`vector<vector<u8>>` 与 `vector<vector<vector<u8>>>` 都能声明、`push_back`、`at(0).at(0)` 取值，`run` rc=0。
**但赋值只能用下标链**：`rows[0][0] = 66;` rc=0；`rows.at(0).at(0) = 66;` 报 `E-Assign-NotPlace`（`method-call` 不是可赋值位置）。

### 3.2 字面量

| 写法 | 结果 |
|---|---|
| `123` / `0xFF` / `0b1010` | rc=0（`0xFF` → 255、`0b1010` → 10） |
| `0o17`（八进制） | `E-Lex-OctalUnsupported` rc=1 —— **没有八进制** |
| `"…"` 转义 | `\n` `\t` `\\` `\"` `\xNN` |
| 字符串格式化 | 只有 `format("v={} {:x} {:>3}", …)`——**没有** `%d` / 拼接运算符 |

### 3.3 无符号算术：**没有溢出诊断，减法会回绕**（实测）

```elench
u64 f() {
    u64 a = 0;
    u64 b = a - 1;      // 18446744073709551615
    return b;
}
```

| 表达式 | 实测值 | 诊断 |
|---|---|---|
| `u64 0 - 1` | `18446744073709551615` | 无 |
| `u8 0 - 1` | `255` | 无 |
| `i64 2 - 3` | `-1` | 无（补码，符号正常） |
| `u64 n - 5`（`n = 2`） | `18446744073709551613` | 无 |

`check` 与 `run` 都不报任何码。**要防下溢就自己判**：`if (n < 5) { … }` 或 `.tu` 里写 `requires n >= 5;`。
（这条是**实现现实**，不是推荐写法——见 §12 的"已知缺口"。）

## 4. 错误与 `T!`

```elench
// .tu
error CountError;

spec maybe(u64 x) -> u64! {
    effects {};
    target { time: { max: O(1) }, allocation: { max: 0 }, };
}
```

```elench
// .eln —— 裸 `return x` 就是 `Ok(x)`；`Err(...)` 必须显式写
u64! maybe(u64 x) {
    if (x == 0) { return Err(CountError::Empty); }
    return x * 2;
}
```

| 规则 | 诊断 |
|---|---|
| `T!` 函数里写 `return Ok(x)` | `E-Return-OkInFallible` rc=1（裸 `return x` 已经是 Ok） |
| 用 `T!` 但模块没有 `error` 声明 | `E-Error-DeclMissing` rc=1 |
| `?` 用在非 `Result` 上 | `E-Try-NotResult` rc=1（**除法不再是 Result**） |
| 整数除零 | **运行期陷阱** `E-Div-ByZero` rc=1，不是 `Err` 变体、也不是宿主异常 |

```elench
u64! half(u64 x) {
    const u64 y = (parse_u64("42"))?;   // `?` 只对 Result 生效
    return y;
}
```

**内置错误枚举**（不用自己声明变体，`src/stdlib.py:ERR_ENUM` 实测）：

| 枚举 | 变体 | 谁会给 |
|---|---|---|
| `Io` | `NotFound` / `Denied` / `Failed` | `try_read_file` / `open_read` / `open_write` / `fs_rename` / `fs_remove` / `file_size` |
| `Parse` | `BadNumber` / `Overflow` | `parse_u64` / `parse_hex` / `base64_decode` |
| `Range` | `OutOfBounds` | `copy_slice` |
| `Json` | `BadToken` / `UnexpectedEof` / `Trailing` / `BadEscape` / `Unsupported` | `json_parse` |

> `Option` 不是错误枚举：它是 `optional<T>`，用 `option_unwrap_or` 解包（`match` 的 `optional::Some`
> 模式只在诊断消息里出现过，本轮没跑通，见 §12）。

## 5. `struct` / `enum` / `match`

```elench
struct Interval { start: u64, finish: u64 }

enum Token { Number(u64), Plus, Str(vector<u8>) }

u64 use_enum(Token t) {
    match (t) {
        Token::Number(n) => { return n; }
        Token::Str(s) => { return s.size(); }
        _ => { return 0; }
    }
}
```

> 变体臂也可以写裸名（`Number(n) => { … }`），解析与检查都认（rc=0）；
> **但正式代码统一写 `Token::Number(n)`**——裸名在多个枚举同处一个模块时容易读错。

| 规则 | 实测 |
|---|---|
| `struct` 字面量 | **只认具名字段**：`Interval iv = Interval { start: 1, finish: 3 };` rc=0。位置式 `Interval iv = {1, 3};`：**`--compat` 且 struct 在同文件且在函数之前 ⇒ 支持**（按字段声明顺序 desugar 成具名字段式，κ/run 与字段式逐字节相同）；**struct 在 `.tu`、或声明在使用之后 ⇒ `E-Struct-PosInitUnsupported`**（检查期就报，不会 run 崩）；个数不符 ⇒ `E-Compat-AggregateArity`。**2026-11-12 更新** |
| 字段访问 | `iv.start` rc=0 |
| 枚举成员 | `Token::Plus`（rc=0）——**统一用 `::`** |
| `enum` 只能写在 `.tu` | 写在 `.eln` → `E-Ai-HasDecl` rc=1 |
| `match` **只能是语句** | `const u64 r = match (t) { … };` → `E-Match-NotExpr` rc=1 |
| `_` 兜底臂**强制** | 少写 → `E-Match-NoDefault` rc=1（即使变体已列全，也是 error 不是 warning） |
| `Ok(v)` / `Err(e)` 臂 | 可用 rc=0（`match (try_read_file(p)) { Ok(d) => … Err(e) => … _ => … }`） |
| `switch` / `case` / `default` | **不存在** → `E-Keyword-Unsupported` rc=1 |

> ⚠ 与 `语法清单.md` 不一致的一处：清单说"enum 值上用 `.` 会报 `E-Member-WrongSep`"，
> 但实测 `t.Num` **rc=0、无诊断**。写 `::` 永远安全，别依赖 `.` 也能过。

## 6. 控制流

```elench
u64 control(const vector<u64>& xs) {
    u64 s = 0;
    if (xs.empty()) { return 0; } else if (xs.size() > 9) { s = 9; } else { s = 1; }

    for (const auto& x : xs) { s = s + x; }                       // 只读引用：不拷贝
    for (auto& x : xs) { x = x; }                                 // 可变引用：改得动容器
    for (auto x : xs) { s = s + x; }                              // 按值：每轮拷一份
    for (u64 i = 0; i < xs.size(); i = i + 1) { s = s + xs[i]; }  // 三段式 → 按 while 推 κ

    for (u64 i = 0; i < xs.size(); i = i + 1) {
        if (xs[i] == 0) { continue; }
        if (xs[i] > 999) { break; }
        s = s + 1;
    }
    return s;
}
```

> 反面：`while (s > 100) { break; }`（体内不改 `s`）报 `E-Loop-CounterUnchanged` rc=1——
> `while` 的条件 MUST 能被静态推界，§6.2 列了 10 种能推的形状。

| 写法 | 结果 |
|---|---|
| `for (auto& x : xs)` / `for (const auto& x : xs)` | rc=0，**不拷贝**（`auto&` 改元素就是改容器） |
| `for (auto x : xs)` / `for (u64 x : xs)` | rc=0，每轮拷一份 |
| `for (u64 i = 0; i < n; i = i + 1)` / `i++` | rc=0（`++` / `--` 是独立 token，`i + +j` 不合成） |
| `for (;;) { … break; }` | rc=0，但 κ = ⊤（等价 `while (true)`） |
| `for (auto it = xs.begin(); it != xs.end(); ++it)` | `E-For-NoIterator` rc=1（**没有迭代器**：无 `*it` / `++it` 取值语义） |
| `a > b ? a : b` | `E-Parse-Expected` rc=1（**没有三元**） |
| `break;` / `continue;` | rc=0；三段式里的 `continue` 仍会执行第三段（desugar 保留 C++ 语义） |

### 6.1 逻辑运算符：**只有符号**（`and` / `or` / `not` 已退役）

```elench
u64 pick(bool a, bool b) {
    if (a && !b) { return 1; }
    if (a || b) { return 2; }
    return 0;
}
```

```text
a and b      // ✗ E-Logic-WordOp（消息逐词教 `&&` / `||` / `!`）
a or  b      // ✗ E-Logic-WordOp
not a        // ✗ E-Logic-WordOp（`!a` 才是逻辑非；`~a` 是按位取反）
b != a       // ✓ 不相等仍是 `!=`
```

优先级（从松到紧）：`||` → `&&` → `|` → `^` → `&` → `== !=` → `< <= > >=` → `<< >>` → `+ -` → `* / %` → `**`（幂，右结合）→ `|>`。
与 C 一致的两个坑（有意保留）：`a & b == c` 是 `a & (b == c)`，加括号。

### 6.2 循环上界：**哪些来源真的能给有限 κ**（本节逐条跑过 `cost`）

| # | 来源 | 形状 | `cost` 的 κ |
|---|---|---|---|
| ① | **字面量常量** | `while (i < 10)` | `κ ≤ 160`（有限） |
| ② | **标量形参** | `while (i < n)`（`n` 是 `u64` 形参） | `4 + n×14 + 14 + 2` |
| ③ | **`x.size()`** | `while (i < xs.size())` | `4 + n(xs)×20 + 20 + 2` |
| ④ | **`x.f.size()`**（结构体字段里的容器） | `while (i < s.v.size())` | `n(s.v)` —— 字段链是**独立尺寸量**，不是 `n(s)` |
| ⑤ | **局部尺寸别名** | `u64 m = xs.size();` 之后 `while (i < m)` | 与 ③ **同一个** `n(xs)`（声明即赋值、之后不再改写才生效） |
| ⑥ | **递减计数器** | `while (j > 0) { j = j - 1; }`（体内**只**做 `j = j - 1` 一类减法，或提前 `j = 0`） | `2 + j×14 + 14 + 2` |
| ⑦ | **位宽上界** | `while (x != 0) { x = x & (x - 1); … }` / `x = x >> 1` / `x = x / 2` | `κ ≤ 1109` / `914` / `914`（常数，每轮至少少一位 ⇒ ≤ 64 轮） |
| ⑧ | **模块级 `const`**（`.tu` 顶层） | `while (i < N)`（`const u64 N = 8;` 写在 `.tu`） | `κ ≤ 132`（有限） |
| ⑨ | **谓词 + `repeats`** | `while (done(xs))` + 该函数的 spec 写 `repeats log2(xs.size()) + 1;` | `2 + (log2(n(xs)) + 1)×19 + 19 + 2`（有限） |
| ⑩ | **`<=` 上界** | `while (i <= xs.size())` | `(n(xs) + 1)×12 + …`（有限） |
| ⑪ | **区间减半**（二分 / 逐位开方） | `while (lo < hi) { u64 mid = lo + (hi - lo) / 2; if (xs[mid] < key) { lo = mid + 1; } else { hi = mid; } }` | `7 + (log2(n(xs)) + 1)×24 + 24 + 2` —— **无端点可定位时按类型位宽封顶（u64 ⇒ ≤ 65 轮）** |
| ⑫ | **索引追逐**（并查集的父指针上浮） | `while (p[root] != root) { root = p[root]; }` | `n(p)×11 + 11 + 2` —— 依据「**κ 只界终止执行**」的口径：走过的下标互不相同 ⇒ 迭代 ≤ `n(p)` |
| ⑬ | **树递归 + `.tu` 的 `recursion depth`** | `place(row)` 的自调用在 `for (u64 col = 0; col < n_; ++col)` 里，`.tu` 写 `recursion depth <= 8` | 激活数 `(D+1)·B^D` ⇒ `9×n(recv.n_)^8` 量级（`D` 字面量、`B` 取外层循环轮数之积） |
| ⑭ | **visited 守卫递归** | 入口无条件 `color[v] = 1`、自调用被 `color[w] == 0` 支配、标记永不回 0 | 激活数 ≤ `n(color)` |
| ⑮ | **区间对半分递归** | 两次自调用各拿一半：`f(xs,lo,mid)` / `f(xs,mid,hi)`，`mid = (lo+hi)/2` | 总激活 ≤ `2×(hi-lo)`（互不相交 ⇒ 叶子 ≤ 区间长度）。**前置条件缺一个就 ⊤**：① 形参恰好 3 个且顺序是 `(容器, lo, hi)`（**容器放在最后会 ⊤**）；② `lo`/`hi` 是**按值**标量、且不被改写；③ 有 `hi - lo <= C` 的**早退**（没有 ⇒ 叶子数没有界 ⇒ ⊤）；④ 只认 `lo + (hi-lo)/2` 与 `lo + ((hi-lo)>>1)`（`(lo+hi)/2` 在 u64 下会溢出） |

**给不出有限 κ 的**（`check` 可能不拦，但 `cost` 判 `κ ≤ ⊤` / 无法判定——**别写**）：

| 形状 | `check` | `cost` |
|---|---|---|
| `while (j / 2 > 0)` | rc=0 | **⊤** |
| `while (a * b < 10)` | rc=0 | **⊤** |
| `while (xs.at(i) > 0)`（数据相关条件） | rc=0 | **⊤** |
| `while (!done)`（bool 标志） | 警告 `E-While-NoBound` rc=0 | **⊤** |
| `while (i < 10) { s = s + 1; }`（不改 `i`） | `E-Loop-CounterUnchanged` rc=1 | — |
| **n 叉递归**（`for (col < n_)` 里自调用，且没有 `recursion depth` / 没有 visited 标记） | rc=0 | **⊤** —— 激活数是 `n^n`，`Cost` 代数表达不了变量指数 |

> **口径**：`check` 只报"明显写错"（计数器没推进 / 条件不是可推形状的 warning），
> **κ 是否有限要看 `cost`**。`E-While-NoBound` 是 **warning**，不阻断 `check`；别把它当"通过"。

### 7.1 三种初始化

```elench
u64 init_demo() {
    array<u64, 4> a;                             // 只声明：N 个零，可直接 a[i] = x
    vector<u64> v;                               // 只声明：空（长度 0）
    array<u64, 4> b = array<u64, 4>(0);          // 值初始化：N 个 0
    array<u64, 4> c = {1, 2, 3, 4};              // 大括号：元素个数 MUST == 容量

```

| 规则 | 诊断 / 实测 |
|---|---|
| `array<u64, 4> dp;` | rc=0：`size()` = 4，`dp[0]` = 0，可写 |
| `array<u64,4> dp = array<u64, 4>(0);` | rc=0，4 个 0 |

| 只声明不初始化 | `vector` → 空（0 次分配）；`array` → N 个零（0 次分配）；标量 → 0 |

### 7.2 下标

```elench
u64 idx(const vector<u64>& xs) {
    u64 a = xs[0];        // 读
    u64 b = xs.at(0);     // 同一个东西，也能读
    return a + b;
}
```

`xs[i]` 与 `xs.at(i)` 语义相同，都 rc=0（`at` 没有被弃用）。**写左侧用 `xs[i] = v;`**——
`rows.at(0).at(0) = 66;` 报 `E-Assign-NotPlace`，而 `rows[0][0] = 66;` rc=0。
越界：常量下标在检查期报 `E-Index-OutOfRange`（rc=1），运行期也报同名码（rc=1）。

### 7.3 每个容器**真正支持**的方法（诊断原文，实测）

| 容器 | 方法 |
|---|---|
| `vector<T>` / `vector<u8>` | `assign` `at` `back` `clear` `empty` `erase` `find` `front` `insert` `pop` `push_back` `size` |
| `array<T, N>` | `at` `back` `clear` `empty` `erase` `find` `front` `insert` `pop` `push_back` `size` |
| `map<K,V>` | `clear` `contains` `empty` `erase` `get` `insert` `keys` `put` `remove` `size` |
| `set<T>` | `clear` `contains` `empty` `erase` `insert` `remove` `size` `values` |
| `unordered_map<K,V>` | `clear` `contains` `empty` `erase` `get` `insert` `keys` `remove` `size` `values` |
| `unordered_set<T>` | `clear` `contains` `empty` `erase` `insert` `keys` `remove` `size` `values` |
| `stack<T>` / `queue<T>` | `clear` `dequeue` `empty` `enqueue` `front` `peek` `pop` `push` `size` `top` |

`FixedVec<T, N>` 是 `array<T, N>` 的旧别名（§3），方法表与 `array` 相同。
**`assign(n, x)` 只有 `vector` 有**（`array` / `FixedVec` 定长，`assign` 会改长度 →
`E-Call-UnknownMethod`）；它返回 `void`（C++ 语义）：**只能当语句写**
`xs.assign(n, x);`，不能拿它的值。`map.values()` 与 `set.keys()` 也报
`E-Call-UnknownMethod`；
`unordered_*` 的 `keys()` / `values()` 都返回**副本**，
顺序**未指定**（实现上是插入序，契约不保证）。

**这些方法各返回什么类型**（2026-11-13 逐个实测；静态口径以
`src/typecheck.py` 的方法返回类型分支为准——`check` 就按这张表拦赋值）：

| 方法 | 返回类型 | 说明 |
|---|---|---|
| `size()` | `u64` | 元素个数（`array<T, N>` 等于 `N`） |
| `empty()` | `bool` | 谓词，可直接写进 `if` |
| `at(i)` / `get(k)` | 元素 | `vector` 是 `T`、`map` 是 `V`；`get` 缺键**运行期报错** |
| `find(v)` | `u64` | **下标**（不是迭代器）；找不到 = `npos` |
| `insert` | `u64` / `void` | `map` / `set` / `unordered_*` → `u64`；`vector` / `array` 的 `insert(pos, v)` → `void` |
| `put(k, v)` | `u64` | **只有 `map` 有**：新键 = `1`，覆盖 = `0` |
| `remove(k)` / `erase(k)` | `u64` / `void` | `map` / `set` / `unordered_*` → `u64`（删掉了 = 1，本来没有 = 0）；序列的 `erase(pos)` → `void` |
| `contains(k)` | `bool` | 谓词；`bool b = m.contains(k);` 合法 |
| `keys()` | `vector<K>` / `vector<T>` | **副本**，改它不动原容器 |
| `values()` | `vector<V>` / `vector<T>` | **副本** |
| `push(v)`（`stack` / `queue`） | `u64` | 恒 `0`（同 C++ 的 `push` 无信息量，这里是计数版） |
| `push_back(v)`（序列） | `void` | `u64 n = xs.push_back(9);` 报 `E-Type-Assign` |
| `assign(n, x)` | `void` | **只能作语句**（C++ 的 `std::vector::assign` 返回 `void`）：`vector<u64> ys = xs.assign(2, 0);` 报 `E-Type-Assign`（初值是 void） |
| `pop()` / `dequeue()` | 元素 | 空容器上报错 |
| `top()` / `peek()` / `front()` / `back()` | 元素 | 空容器上报错 |
| `clear()` | `void` | |

> **`u64` 不是 `bool`**：`bool b = m.insert(k, v);` / `bool b = m.put(k, v);` /
> `bool b = m.remove(k);` 都会被 `check` 拒绝（`E-Type-Assign`：`b` 声明为 bool，
> 初值是 u64）。返回 `bool` 的**只有 `contains` 和 `empty`**。
> 反过来 `u64 n = m.contains(k);` 也报同一条码（初值是 bool）。

**新旧名对照**（旧名还能跑，但报 `W-Builtin-Deprecated`，v0.73 移除）：

| 旧名 | 新名 |
|---|---|
| `length()` | `size()` |
| `push(v)` | `push_back(v)` |
| `is_empty()` | `empty()` |

**真不存在的名字** → `E-Call-UnknownMethod`（rc=1，消息里列出该容器支持的方法）：
`len()` / `append()` / `size` 之外的猜测名；`map.at(k)` 也不存在（`map` 没有 `at`）。

### 7.4 `map`：`m[k]` / `insert` / `put` / `get` 各自算什么（实测）

| 写法 | 键不存在 | 键已存在 | 返回 | 实测 |
|---|---|---|---|---|
| `m[k]`（读） | **插入 `V{}` 并返回它** | 返回已有的值 | `V` | `m[7]` → `0`，`size()` 2→3 |
| `m[k] = v;` | 插入 | **覆盖** | `()` | rc=0 |
| `m.insert(k, v)` | 插入 | **什么都不改** | `u64`（插入了 = `1`，键已存在 = `0`） | `insert(1,10)` → `1`；`insert(1,99)` → `0` |
| `m.put(k, v)` | 插入 | **覆盖** | `u64`（新键 = `1`，覆盖 = `0`） | `put(2,20)` → `1`；`put(1,99)` → `0` |
| `m.get(k)` | **运行期报错** | 返回值 | `V` | `map.get：键 7 不存在（先用 contains 判断）` rc=1 |
| `m.contains(k)` | `false` | `true` | `bool`（谓词） | `if (m.contains(3))` → 通过 |

```elench
u64 map_demo() {
    map<u64, u64> m;
    u64 a = m.insert(1, 10);   // 1：新键，插进去了
    u64 b = m.insert(1, 99);   // 0：键已存在，**不覆盖**（m.get(1) 仍是 10）
    u64 c = m.put(2, 20);      // 1：新键
    m[3] = 30;                 // 插入 / 覆盖
    m[2] += 1;                 // 读-改-写（先保证键存在）
    if (m.contains(3)) {
        return m.size() + m.get(3) + a + b + c;
    }
    return 0;
}
```

- **`map` 是有序的**（键序迭代），查找/插入/删除 `O(log n)` 确定；`unordered_map` 才是哈希。
- **`insert` / `put` 返回 `u64` 计数，不是 `bool`**：`bool b = m.insert(k, v);`
  会被 `check` 拒绝（`E-Type-Assign`：`b` 声明为 bool，初值是 u64）。
  `map.insert` 不覆盖（插进去了 = 1）；`map.put` 覆盖（新键 = 1、覆盖 = 0）。
- **别的容器不一样，别套这张表**：`unordered_map.insert(k, v)` **覆盖**已有键，
  且返回值**恒为 `0`**（新键也是 0）；`set` / `unordered_set` 的 `insert(v)` 也返回
  `u64`，同样恒 `0`。四种容器的 `insert` 都是 `u64`（只有序列的 `insert` 是 `void`）。
- **`contains(k)` 返回 `bool`（谓词）**：`if (m.contains(k))` 直接写，`bool b = …` 也收；
  `if` 条件只收 bool / 指针，所以它**不能**是 u64。要 0/1 计数的是
  `insert` / `put` / `remove` / `erase`（返回 `u64`，也没人写进 `if`）。
- `map` 的 range-for 元素是 **`(键, 值)` 二元组**：`for (const auto& kv : m) { u64 v = kv.1; }`。
- 键只要**全序**：`map<vector<u8>, u64> m; m["k"] = 1;` rc=0。

### 7.6 嵌套容器：`vector<vector<u8>>`

```elench
u64 rows_demo(const vector<vector<u8>>& rows) {
```

### 8.3 明确**没有**的东西

## 9. 决策点 `?!`

`.tu` 里 `choose`，`.eln` 里 `kernels` —— **`?!` 必须有 `benchmodel`**，否则 `E-Bench-NoModel` rc=1。

```elench
// .tu
spec make_u64s() -> vector<u64> {
    effects { nondet };
    target { time: { max: O(1) }, allocation: { max: 1 }, };
}

spec total(const vector<u64>& xs) -> u64 {
    effects {};
    benchmodel {
        data  { xs = make_u64s(); }
        scale { xs in range(1, 1024, *2); }
        seed  = 1;
    };
    target { time: { max: O(xs.size()) }, allocation: { max: 0 }, };
    choose kern(const vector<u64>& xs) -> u64 {
        over { by_index, by_iter };
        objective time;
    };
}
```

```elench
// .eln
vector<u64> make_u64s() {
    vector<u64> v;
    v.push_back(1);
    return v;
}

u64 total(const vector<u64>& xs) {
    return (?!kern(xs));
}

kernels kern(const vector<u64>& xs) -> u64 {
    by_index {
        u64 s = 0;
        u64 i = 0;
        while (i < xs.size()) { s = s + xs.at(i); i = i + 1; }
        return s;
    }
    by_iter {
        u64 s = 0;
        for (auto x : xs) { s = s + x; }
        return s;
    }
}
```

| 项 | 规定 |
|---|---|
| `benchmodel` | `data { … }` 用 `=`；`scale { xs in range(lo, hi, *2); }` 用 `in`；`seed = 1;` |
| 生成器 | MUST 是**已声明且有 `spec`** 的函数（否则 `E-Bench-BadGenerator` rc=1） |
| `benchmodel` 没有 `?!` | 警告 `W-Bench-Unused`（rc=0）——**没有 `choose` 就别写 `benchmodel`** |
| `?!` 的成本 | 所有候选的 **max**（选错也不违约） |
| 候选内联 | `kernels` 的候选**内联进宿主**，能看见宿主局部变量 ⇒ 候选里的局部名 MUST 与宿主不同 |
| `bench` | 函数体含 `?!` 时 `bench` 拒绝（B-18），用 `measure` |
